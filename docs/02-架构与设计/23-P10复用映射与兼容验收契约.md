## 不变契约

- 唯一循环仍为 `Agent.Chat`，应用装配仍在 `internal/service/chat.go`；CLI/Web 共享应用服务。
- Session/Turn/Step ID、取消、流式消息、工具卡与审批卡结构保持兼容；压缩内部消息不覆盖已有会话历史，不暴露原始思考。
- `executeTool` 的 Policy → 真人审批 → 执行前核权 → Executor 链不旁路；批量拒绝、取消、写失败停止剩余调用的行为保留。
- Secret 值只进入获批当前轮请求；压缩、结果归档、摘要、UI/SSE、审计和后续轮次均不得含明文。压缩请求必须使用安全消息副本，不能直接复制含当前轮 Secret 的请求。
- 不实现专家、独立 Runtime、跨进程任务调度；不把重启中断宣传为无损恢复。

## 基线与出口

入口：`go test ./internal/agent -run TestAgentFaultBaseline -count=1 -v`。默认只跑夹具和脚本模型的确定性预检。显式 `AEGISOPS_EVAL_REAL_MODEL=1` 后使用 `AEGISOPS_EVAL_ENDPOINT`、`AEGISOPS_EVAL_MODEL`、`AEGISOPS_EVAL_API_KEY` 调用真实模型；缺配置即失败。夹具为合成只读数据，不连接集群、不注入故障、不运行 shell，不替代真实集群联验。

输出 JSON 记录夹具摘要、模型标识、完成情况、逻辑模型请求/工具次数、Token 与耗时（客户端内部 HTTP 重试不计为额外逻辑请求）。`review_answer` 提供经通用脱敏及端点/密钥精确脱敏的回答供人工复核。证据标记匹配只是自动初筛，根因正确性与未编造证据仍需人工复核，不能据此宣称准确率提升。端点、密钥和未脱敏回答不落评测日志。保存 `go test -v` 日志并记录实际 git 提交、模型版本、推理设置与运行日期，改造后使用同一配置重跑。评测固定非流式、temperature=0、max_tokens=2048、每请求 60s、总轮次 5、工具次数 5、单例总时限 2min；它验证 Loop，不替代 SSE 兼容回归。

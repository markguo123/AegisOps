## 1. 架构结论

优化现有 Go Agent Runtime，以 HolmesGPT 为主要逻辑与代码来源。不引入 LangGraph、Google ADK 或第二套 Loop。当前工具集与 Skill 继续承担能力扩展；本轮不建设专家 Agent、通用 Agent 平台或独立 Runtime 服务。对外可描述为“Go Agent Runtime，借鉴 HolmesGPT 的上下文与工具结果管理机制”，实现验收前不能宣称迁移完成或使用其完整框架。

上游成熟实现、提示词和测试资产优先搬运；Python 实现按原逻辑移植 Go，只适配我方接口。避免重新设计成熟机制，也不并排维护两套执行器或状态事实源。随实现记录固定提交、代码来源、必要适配和原有声明到 docs/CREDITS.md。

## 3. 本轮核心范围

请求预算包含消息、工具 Schema 和输出预留；模型窗口来自配置，无法精确计数时使用明确的保守估算。压缩保留目标、集群/权限范围、证据引用、已执行动作、拒绝和未解决项。压缩失败必须有次数与资源上限。

大结果先预览、再按需读取；复用既有对象存储和归属校验，用结构化工具读取，不允许模型任意读取服务端文件。普通数据按既有脱敏规则处理；Secret 明文仅当前轮获批模型请求可用，不进入摘要、存储、事件或后续轮次。

失败反馈区分权限拒绝、目标不可达、参数错误、资源不存在及执行结果未知。只读允许受控重试；权限拒绝不重试，写操作结果未知先对账或人工核实。单工具失败不终止整个调查，不做无限重试。

## 4. 保持现有业务边界

主 Agent → 工具提案 → 确定性 Policy → 必要的真人确认 → 当前权限复核 → Executor → 结果反馈。模型不掌握权限，自动审批不引入子 Agent。高危、shell、非交互 exec、Secret 按需读取仍遵守现有规则。

底座阶段兼容既有审批卡、Session/Turn/Step、取消和 SSE 协议；完整审批记录、重启后待审批恢复、关键执行记账归 P4，不以跨进程任务系统作为底座优化前置条件。审批恢复重新校验身份、集群、凭据版本、参数和授权；未知写结果不重放。当前进程中运行的任务遇重启可中断，不能宣传任意任务无损恢复。

## 6. 验收

同模型、同工具权限、同输入和故障夹具比较改造前后，记录根因/证据正确性、完成率、请求、Token、耗时与失败原因。不得预先承诺改善比例；安全和证据正确性不得退化。

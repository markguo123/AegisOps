# AegisOps 全量工具优化与改造方案

2026-11-27 · v4.0.5 新特性 · 总体设计已确认，待实施 · 代码基线 main / 6485ece

## 1. 产品决策

本方案覆盖当前模型可以调用的内置工具、按配置启用的工具、外部 MCP 工具适配器及独立 CLI 巡检 MCP。以一次真实排障为交付单位：用户指出对象或症状，Agent 找到正确目标、取得足够证据、解释仍然未知的部分；用户授权变更后，Agent 能说明变更结果以及原症状是否恢复。

| 决策 | 理由 | 直接影响 |
| --- | --- | --- |
| 优先修复会改变诊断结论的输出 | 错误的目标、范围、时间或计数会污染后续推断，即便模型选对了工具 | 首批交付可独立发布，无需等待工具改名或模型升级 |
| 合并模型可见入口，保留按 kind 的领域摘要 | 对象、列表和诊断分别只有一个规范入口 | 约 36 个内置名称收敛到 15 个；普通读取与取证由 22 个收敛到 5 个 |
| 统一对象诊断入口 | 扫描、规则和证据采集继续复用现有应用服务 | 模型以 kind 和目标选择诊断策略 |
| 复用现有 Gateway、Authorizer、Executor、Approval 与 ScanService | 目录负责描述能力；平台和集群执行边界负责裁决每次操作 | 规范入口和新增参数均需经过同一边界 |
| 第一阶段沿用现有工具选择方式 | 缺少真实模型的误选率、调用次数及上下文成本基线 | 暂缓动态路由、新通用 shell、整套结构化写工具和新增诊断 Agent |

本方案的负责人按能力分工：工具维护者定义输入输出，Scanner/执行器维护者保证采集与执行事实，Agent 维护者负责选择和续查，Web/CLI 维护者按同一结果展示。产品验收以用户能否得出正确结论为准。

## 2. 工具处置清单

以下按公开名称列出。会话可用集合随配置、运行入口、授权与外部服务而变化。

| 当前工具 | 决定 | 目标行为 |
| --- | --- | --- |
| get_pod | get_resource(Pod) | 给定 namespace 和精确名时先 GET。仅明确 NotFound 才允许进入候选发现；前缀候选回传真实名称和匹配依据。按工作负载找 Pod 时用 ownerReference/UID，Deployment 经 ReplicaSet 关联。禁止把候选自动当成变更目标。 |
| get_pods、get_nodes、get_configmaps、get_resources | list_resources | 通用入口提供资源名发现；专用入口保留状态或配置摘要。按资源声明可用 selector、默认页大小、上限及可翻页性。kind 的说明、输入校验与实现来自同一支持表，修正 events 声明与实现不一致。 |
| get_deployment、get_statefulset、get_daemonset、get_replicaset | get_resource(kind) | 返回期望与观测状态，提供 UID、代际及可获得的 owner 引用。判断发布进度时说明控制器是否已观测当前代际。按需下钻 Pod。 |
| get_node、get_node_usage | get_resource(Node)；指标走 get_node_usage | 区分节点状态与采样用量，返回采样时间。两次读取之间节点消失时仍返回用量；容量缺失或为零时百分比标记未知。metrics 不可用时说明缺失来源。 |
| get_service、get_endpoints、get_endpointslices | get_resource；EndpointSlice 集合走 list_resources，service 参数转标准标签 selector | Service 描述 selector、端口和类型；EndpointSlice 优先用于后端就绪诊断，Endpoints 服务兼容场景。分别报告 subset、地址及就绪统计，区分缺省 ready 与显式 false，说明计数单位；双栈地址数不可直接当作 Pod 数。 |
| get_pvc、get_pv、get_storageclass、get_namespace | get_resource(kind) | 使用稳定目标引用。PVC/PV 关联带绑定依据；关联对象不在当前授权范围时保留已知事实并标明缺口。namespace 的标签、注解沿用不可信数据处理。 |
| get_events | 改造 | 按对象 UID、时间窗、类型和条数过滤；对象名查询明确是否跨实例。统一事件时间计算，排序后取最近 N 条，对并列时间使用稳定次序。与 get_pod 内联事件共享逻辑。 |
| get_logs、get_previous_logs | get_logs(instance=current/previous) | 当前实例与上一次容器实例含义不同。回传容器、实例类型、观察窗口、行数/字节限制与截断原因。区分无日志、上一次实例不存在、无权读取和读取失败。 |
| get_configmap、get_secret_info | get_resource；Secret 元数据按发布门槛使用独立的 get_secret_info 或专用元数据分支 | 配置对象优先给出键、变量引用和脱敏配置片段；Secret 元数据走普通读取。配置差异结论引用实际字段、对象和版本。 |
| get_secret_value | 收紧操作选择 | 模型调用必须显式指定 check_nonempty、compare_config 或 read。缺省操作在申请同意前返回参数错误。继续复用服务端判空、比较与绑定校验。明文模式只在确需内容时申请。 |
| scan_cluster | 保留 | 作为集群或 namespace 体检入口，输出实际覆盖范围、关键采集失败、健康分适用范围及 Finding 摘要。 |
| scan_pod、diagnose_pod | diagnose_resource(Pod) | 规范入口按 kind 分派，Pod 策略提供规则与证据驱动的单 Pod 诊断。旧工具名随本版本下线。深查请求按已有证据补采前次日志或事件，避免相同参数重复运行一次巡检。 |
| diagnose_node、diagnose_workload | diagnose_resource(kind) | 先落实目标级输出隔离，再优化采集范围。只归属直接命中或有可追踪关联的 Finding；环境概况单列。全域扫描仍有必要时返回实际开销与缺口。 |
| kubectl | 保留通用兜底 | 结构化工具无法表达时使用。沿用完整命令语义分析、逐目标授权和执行隔离。为可识别变更返回实际目标及可验证的后续观察；未知结果的写入须先读回状态。 |
| create_resource | 保留并强化已有工作流 | 沿用 dry_run、proposal_id、apply 和可选 verify。多个对象分别报告提交与就绪状态，部分成功后先核对现状再处理剩余对象。 |
| exec_pod | 保留独立入口 | 明示集群、namespace、Pod、容器和非交互命令；每次取得真人审批。运行结果保留退出状态、截断及超时信息。 |
| list_skills、get_skill、ask_user_question | 保留 | Skill 附来源和适用条件，仅提供方法文本。对象存在歧义且现有证据无法确定时，通过提问展示候选及其区分信息；普通澄清、敏感读取同意、变更审批在界面上各有明确用途。 |
| read_tool_result | 保留 | 用于当前轮已产生的大结果分页。指明引用寿命、偏移和结束条件。它与 Kubernetes 列表翻页分别处理展示预算和源端读取成本。敏感的 ModelOnly 内容不能进入可回读缓存。 |
| Web 外部 MCP 工具（按服务器白名单注册） | 改造适配层 | 保留原有管理员范围、白名单和审批。结构化结果保留类型；区分连接、超时、远端业务错误、类型不支持和响应过大。远端返回的文本统一视为不可信。 |
| CLI MCP 的 start_inspection、get_inspection_status、get_inspection_report | 保留三个阶段 | 启动返回任务引用；状态说明运行、完成或失败及安全原因码；报告保留分页与实际采集范围。客户端能区分任务未完成、引用过期及报告页过大。 |

### 2.1 v4.0.5 发布目录与接入边界

配置全部启用时，模型侧规范名如下；按配置、身份和会话能力裁剪。实现层继续保留领域 Reader、摘要函数和确定性诊断器。独立 CLI 巡检 MCP 的三个入口与动态接入的远端工具单独计数。

| 能力 | 规范名 | 首版输入约束 |
| --- | --- | --- |
| 5 个普通查询与取证入口 | `get_resource`、`list_resources`、`get_events`、`get_logs`、`get_node_usage` | get 必填 kind/name，list 支持 kind、namespace、labelSelector、fieldSelector、limit、continue；两者按支持表校验操作、作用域和字段。日志保留 namespace/pod、容器、行数、时间窗，新模型 Schema 必选 instance=current/previous。 |
| 5 个产品专用入口 | `scan_cluster`、`diagnose_resource`、`get_secret_value`、`create_resource`、`exec_pod` | diagnose 必填 kind/name；Pod、Deployment、StatefulSet、DaemonSet 要求 namespace，Node 按集群范围；Service 复合诊断列入后续数据验证。其他入口沿用原有开关和参数，Secret 新调用显式选择 operation。 |
| 1 个通用操作入口 | `kubectl` | 使用受控命令参数、现有命令计划与执行器。 |
| 4 个会话辅助入口 | `list_skills`、`get_skill`、`ask_user_question`、`read_tool_result` | 发现方法、读取正文、消除歧义和本轮结果分页分别建模。 |

Secret 元数据合并有独立发布门槛：get 与 list 分别复用既有 Secret 信息单查与列表的字段白名单，强制 namespace，只给名称、类型、immutable、键名等安全字段，禁用原始输出和任意字段投影。通用动态读取路径不得承接 Secret。任一分支无法证明满足要求时，两个通用入口都排除 Secret，单独保留 get_secret_info，发布目录为 16 个。Secret 直接 kubectl 访问仍硬拒绝。

### 2.2 路由规则与工具发现

| 用户任务 | 首选 | 下一步条件 |
| --- | --- | --- |
| 已知对象、列表和摘要字段 | get_resource / list_resources | 明确要求 Schema 未覆盖的字段、受支持的原始取证或长尾资源时，直接用受控 kubectl；无需先做注定无用的摘要查询。 |
| 已有对象发生故障、集群体检 | diagnose_resource / scan_cluster | 结果明确缺前次日志、事件或某字段时只补这一项；证据足够即回答。 |
| 用户明确要日志、事件或用量 | 相应专项工具 | 按对象 UID、容器实例或采样时间限定证据。 |
| 创建、容器执行、Secret 内容 | 各自专用流程 | 被拒绝或撤权后结束该次操作；不得换路径重试。 |

LLM 在当前目录内选证据。服务端验证实际调用；首版无需独立意图分类模型。同步更新原生 function calling、兼容模型的文本工具说明、系统提示和内置 Skill 示例，消除“任何诊断必须先拿完整 YAML”与“摘要足够即停止”的冲突。

**search_tools 决策。** 本版不注册为第 16 个常驻工具。固定 15 个入口直接公布；若所有 Schema 已在上下文，再搜索一次没有节省输入。Skill 目录发现的是排障方法，不能代替工具发现。为后续扩展保留注册表中的规范名、能力域、用途、关键词与可用条件。外部 MCP 增长后，若审计表明 Schema 成本或误选成为瓶颈，在同批任务上比较全目录与“核心目录 + 按需发现”。后者仅为当前会话发现已启用且可见的扩展能力，命中后才加载定义；发现不授予权限，执行时重新鉴权。评估总 token、命中率、漏召回、额外往返和耗时，再决定是否上线。

## 3. 统一输入输出及执行规则

### 3.1 查询范围和目标

目标引用复用当前集群 ID、namespace、资源类型、名称；实例相关证据尽可能带 UID 和 resourceVersion。区分请求目标、实际读取范围和结论适用范围。例如，诊断某 Deployment 时即使底层读取了整个 namespace，返回的对象结论也只能引用该对象及可证明的关联资源。若输出环境健康分，必须明确其范围。

列表先将支持的 labelSelector、fieldSelector 下推 API Server，再在服务端做有界整理。仅在确有分页机制时返回游标；游标绑定集群、查询和范围，每页重新鉴权。默认建议每页 50、上限 200，作为压测起点；事件保留更小的默认值。普通列表按页计数；只有完整遍历或数据源提供可靠总量时才给出总数。获取最近事件若受读取预算限制，应注明排序覆盖的窗口。日志保留独立字节预算。HolmesGPT 的可借鉴点是 selector 和实际查询范围的表达，落地沿用 AegisOps 自有 Reader 和执行路径。

### 3.2 证据、部分成功和结果大小

扩展现有 ToolResult 与展示层，用可选字段兼容已有消费者。同一个工具事件向模型、Web、CLI 和报告提供一致的公开事实。按结果类型填充，避免小工具也携带整套空字段。

| 结果事实 | 建议字段或表达 | 生成位置 |
| --- | --- | --- |
| 目标与来源 | 目标引用、采集时间、时间窗、来源工具事件 | 实际执行和采集端填写 |
| 覆盖与完整性 | 实际范围、已返回数、是否还有下一页、截断原因 | 查询端记录；展示层另记展示截断 |
| 部分失败 | 沿用 partial，附缺失的证据来源、稳定错误码、是否可重试 | 工具聚合时保留每个子读取结果 |
| 结论与依据 | 观察事实、关联依据、待验证项及已有事件引用 | 工具交付事实，Agent 负责归纳并引用 |
| 执行与验证 | 分开记录提交结果、对象状态与原症状验证 | 执行器回填操作事实，后续只读取证更新验证状态 |

例如，Pod GET 成功、Events 被拒时，返回 Pod 状态和 UID，整体为 partial，事件子项为 RBAC_DENIED。模型可以判断容器正在重启，同时明确缺少事件证据。完整读取且匹配为零才报告“在本次范围和窗口内未发现事件”。认证失败、对象不存在和工具不可用应在来源处映射错误码，字符串推断仅用于兼容旧结果。

### 3.3 能力声明与授权

在现有注册表与 Capability/OperationFacts 上增加契约校验，检查公开名、参数、支持模式、结果种类、依赖能力和替代入口。副作用、数据敏感度、是否强制真人确认分别描述。例如，Secret 判空属于读取，仍然每次需要获准。先增补独立语义和测试，再迁移依赖 IsReadOnly 的调用方；过渡期维持更严格的有效审批结果。

平台 Authorizer 按实际目标和动作裁决，Gateway 与 Kubernetes RBAC 约束请求；分页、回查、Skill 与会话记忆均不得产生新授权。无权直接返回拒绝；Secret/key 同意后重新校验当前权限、目标和凭据。ModelOnly 明文仅进当前轮模型，聊天、报告、历史、缓存和审计脱敏。人工点击 reveal 继续走独立接口、重新鉴权及短时内存展示。保持现有可证明只读组合、真实 shell、Pod exec 和自动化的审批边界。

**ClusterRoleBinding 读取口径（已确认）**：集群级 read 授权允许读取，namespace 授权不包含该集群资源。结构化预检、命令预检和实际 API 请求统一使用资源策略，每个组合命令分支单独鉴权。撤权后拒绝新请求，集群 Kubernetes RBAC 继续约束实际读取。

### 3.4 工具接入规范 v1

统一调用链：会话注册与裁剪 → 按公开名和入参定位能力 → Schema 与业务参数校验 → 从可信会话取得身份、集群和凭据 → 生成实际操作目标 → Authorizer 校验 → 按策略审批及复核 → 有界执行 → 脱敏与结果呈现 → 审计与证据引用。模型只能提交工具名和业务参数。命令路径沿用 Gateway 在实际请求处的裁决；紧邻执行的撤权检查必须保留。

在现有 Tool、Registry、Capability/OperationFacts、ToolResult 上增量实现。每个适配器声明稳定名称、用途、输入模式、能力域、支持矩阵、依赖、执行副作用、数据敏感度及强制审批条件。平台提供超时取消、错误映射、输出预算、审计关联、展示和合约测试；适配器负责数据源鉴权对接与领域事实。新普通读取工具接入不应要求修改 Agent 循环。监控、日志、工单等未来数据源沿用此流程，自行定义租户、对象和动作；未知能力域默认拒绝。v4.0.5 用通用读取、Secret 比较、外部 MCP 三类适配器验证规范，不提前开发未来数据源。

## 4. 变更后的故障验证

用户要求修复时，保留原始症状、目标和可比较的观察窗口。执行结果至少能区分已提交、已拒绝、已失败及结果未知。连接中断导致提交结果未知时先查询目标状态和版本；未经核实的重复变更不得自动重放。每次新变更仍按现有审批策略处理。

以 Deployment 重启为例，命令退出成功只能确认命令执行结果；观察新代际与 Ready 副本可验证发布进度；原问题若是请求持续 503，则还需要该服务的可授权观测证据。平台缺少该信号时，最终答复应明确“发布已就绪，503 是否恢复仍待验证”。用户仅要求执行命令时，按任务约定返回执行结果，避免隐性扩大验证范围。首版复用现有目标读取与 create 的 verify，不引入后台自动修复。

## 5. 兼容、上线与回退

1. **读端先行。** 先让 Agent、CLI、Web 和报告识别新增可选字段和 partial，再升级生产者。旧记录缺少范围、UID 或时间时显示“未记录”，不可倒推。旧会话按当时调用名称和结果原样展示。
2. **下线重复入口。** 运行时仅注册规范工具名。升级后旧名调用按未知工具处理，模型根据当前目录重新选择入口。复用 Reader、摘要和诊断策略，删除重复的工具包装与别名分派。
3. **敏感输入单独迁移。** 旧历史可回放；新发起或恢复执行的缺省 operation 请求必须重新明确意图。对旧客户端返回 INVALID_ARGUMENT 并提示合法模式。禁止以兼容为由自动补 read。回退工具目录或界面时也应保留该限制。
4. **按风险发布。** 先灰度只读结果与大列表，再上线统一诊断入口，最后启用变更验证和 MCP 增强。出现错误归因、范围扩大或审批行为变化时暂停该批。回退以已验证版本为单位；可在当前版本关闭受影响的能力。安全域问题优先关闭受影响能力。
5. **控制存储影响。** 首版复用工具事件与既有脱敏存储，不保存整页原始资源或重复日志。跨轮沿用方案 31 的观测引用；工具页游标和本轮结果缓存按自身生命周期处理。

### 5.1 配置、旧调用和运行中的会话

历史会话按原名和原结果展示，回放只读取历史记录。升级后新调用统一使用当前规范目录。旧名未知时应依据当前 Schema 发起新调用，原有审批不随工具切换继承。

旧工具名仅用于解析已有 `agent.disabled_tools` 配置。规范名禁用覆盖全部子能力，旧项限制对应 kind 或实例。多个旧入口覆盖同一能力时，保留仍启用路径的并集。例如禁用 `get_previous_logs` 只关闭 previous，禁用 `get_logs` 关闭整个日志入口。禁用 `exec_pod` 继续约束底层命令通道。配置迁移与资源授权分别在目录和请求边界执行。

`get_logs` 必须显式指定 `instance=current/previous`。旧会话保持原展示，未完成的敏感操作须按当前契约新发起，重新校验权限并取得本次确认。

## 6. 实施次序与验收

| 批次 | 交付与依赖 | 可判定的发布条件 |
| --- | --- | --- |
| A 证据纠错 | 工具与 Scanner 维护者修复 Pod 目标解析、事件排序与关联、后端计数、节点指标、定向摘要和 Secret 缺省操作；授权负责人裁决策略分歧 | 同名重建、拒绝读取、旧事件及缺失指标均能产生正确结果；缺省 Secret 操作在审批与读取前失败；策略分歧有书面决定和一致测试 |
| B 查询与目录 | 在 A 的事实口径上，Reader 支持筛选分页，工具注册与 Schema 一致，模型入口合并，消费者支持部分成功 | 百条以上结果可翻页；窄范围查询实测下推；旧名调用被拒绝；禁用配置语义、旧历史展示和多 namespace 鉴权通过回归 |
| C 执行与扩展 | Agent/Executor 实施变更验证，MCP 维护者处理结构化结果、错误与巡检状态；沿用既有审批和审计 | 能区别命令完成、对象就绪、原症状恢复；不确定提交不会重复写入；MCP 超时、远端拒绝和任务过期可辨识 |
| D 场景验收 | 产品与运维在相同模型、配置、凭据和故障数据下对比基线与候选版；覆盖普通 namespace 用户与管理员 | 下列必测场景无错误事实、无授权回归；记录首选工具、重复调用、API 请求数、模型输入量和端到端耗时后决定是否继续优化路由 |

**首轮验收样例**

| 场景 | 必须观察到的行为 |
| --- | --- |
| Pod 重建后仍在重启 | 只把当前 UID 的事件归给当前 Pod；读取 previous 日志时标出容器实例；证据不足时保留假设 |
| 单个工作负载所在 namespace 有其他告警 | 工作负载结果排除无关 Finding；namespace 分数不会被展示为工作负载健康分 |
| Service 有一个 subset、多个后端且部分就绪状态缺省 | 正确区分地址数、subset 数、显式未就绪和未提供状态；给出进一步判定所需依据 |
| namespace 用户只能读 Pod，不能读某项关联证据 | 返回已有状态和证据缺口；禁止表述为“无事件”“对象不存在”或已经排除故障 |
| 只需确认 Secret 与配置是否一致 | 申请明确比较操作，审批后重验，只输出比较结论；审批拒绝或比较目标版本变化时停止该次操作 |
| 大列表、缓存回读及中途撤权 | 列表按源端续页；当前轮回读只访问允许缓存的脱敏结果；新 Kubernetes 请求在撤权后被拒绝 |
| 发布命令已成功但服务仍有 503 | 分别呈现执行、发布和原症状证据；业务恢复没有证据时保持待验证 |
| MCP 服务超时或巡检已过期 | 返回可处理的错误或状态；Agent 可解释下一步，不把工具失败当作集群故障 |

先建立基线，再承诺性能数字。首发硬门槛是范围、事实和授权用例全部通过；模型工具命中率、调用成本与时延按相同场景报告实际差值。回归执行覆盖工具、Agent、服务层、CLI、前端和 MCP；发布前运行项目规定的全量 Go 测试与 vet，逐项记录当前基线已有失败、修复和剩余风险。真实模型与真实集群验收单独留存脱敏证据。

### 6.1 工程落点与发布证据

| 工程落点 | 首要交付与检查 |
| --- | --- |
| internal/tools、internal/tools/k8s、internal/service/chat.go | 单一能力支持表生成注册、Schema 与禁用映射；验证旧名从注册表移除，并验证旧禁用项的迁移。生产注册表快照覆盖全开、按需读取关闭、禁用部分 kind 和无 metrics。 |
| internal/agent、internal/approval、internal/k8sgateway、internal/executor | 更新选择示例及名称依赖；按操作事实校验每一个 get/list/logs/exec 和复合诊断的子请求。检索遗留工具名，只保留禁用配置和历史展示所需的旧名。覆盖审批后撤权、规范入口撤权检查、越权无审批。 |

先验证旧会话可读、权限无扩大、敏感信息无新增出口及必测场景证据正确；任一不满足即阻断。性能收益按任务分组公布。精简目录若在一类任务上持续退化，定位字段缺失、工具说明或路由问题后重新灰度；不得用目录数量代替质量验收。发布物附工具映射、配置变化、回退步骤和真实环境验收记录。

# Agent 跨轮续查与 Secret 诊断交互优化

2026-11-27 · v1.1 · 基线 v4.0.1 · 目标 v4.0.4 · 评审修订稿，待实施

## 1. 发布范围

本版解决两件事：同一次故障排查在多轮 Chat 中能够接续，以及 Secret 相关诊断能够用最少的敏感信息回答问题。首版覆盖平台 Chat，沿用现有 Agent Runtime、会话、审批、执行和审计链路。全量工具盘点和改造暂缓。本方案只涉及支撑这两项目标的输入、输出和接入点。

## 2. 已确认的问题

| 问题 | 观察到的现象 | 影响 |
| --- | --- | --- |
| Secret 诊断围绕读取明文展开 | 会话 20261125-5058 对同一个 Secret 成功读取六次，每次一个 key。Agent 要回答的是当前配置与 Secret 中的账号是否一致。用户随后直接在聊天中贴了凭据，原文出现在会话导出。 | 重复确认，模型接触的敏感信息超出诊断所需，用户转向普通消息提交凭据。 |
| 配置引用与字面值的脱敏粒度不足 | 配置文本中的变量引用所在行被遮住，Agent 多次用只读命令核对相同信息。 | 难以判断值的来源，增加重复查询和错误建议。 |
| 跨轮调查缺少可复用的证据和进度 | 会话已有消息与工具回放，但该次排查反复读取相同目标，也把已观察到的配置差异推演为未经实际发信验证的根因。 | 用户补充信息后容易重新取证，最终报告混淆配置事实、推断和验证结果。 |

报告用于说明设计缺口。SMTP 的实际失败环节在报告结束时仍待验证。方案正文只记录现象和会话编号。

## 3. 跨轮续查

### 3.1 会话内的诊断状态

在现有会话上增量保存有界、可选的诊断状态。首版围绕会话正在处理的故障，支持多个已授权的关联对象。上下文压缩仍用于控制模型输入，续查所需的关键记录由服务端独立保留。

| 记录 | 最小字段与权威来源 |
| --- | --- |
| 目标与进度 | 用户目标、当前阶段、稳定集群 ID、namespace、资源类型与对象名。目标来自用户选择及服务端确认的实际执行范围。 |
| 观测 | 类型、脱敏结果、采集时间、实际目标、来源轮次及工具事件。可用时带 UID、resourceVersion 或观测窗口。由服务端依据成功工具结果生成。 |
| 假设与下一步 | 相关观测 ID、待验证项、预期能区分哪些原因的下一条证据。模型可以提议和归纳，服务端校验引用存在且范围匹配。用户陈述单独标记来源。 |
| 用户决策和变更结果 | 引用现有审批、拒绝及执行记录。区分待确认、已拒绝、已执行、执行结果未知和原故障已验证。 |

### 3.2 执行流程

首版先接入 Pod 重启与配置核对所需的结构化结果。每个接入点声明可以生成的观测类型、必要字段及证明范围。服务端只从结果中提取这些字段。日志正文、配置文本和模型归纳都不能直接写成已确认的事实。工具调用成功只说明采集完成。例如，日志查询无匹配只能支持“该实例在指定窗口未检出该错误”；Pod 就绪只能支持该时刻的就绪状态。工具失败、返回被截断或采集范围不足时，保留缺失项。

1. 每轮根据当前身份和绑定目标读取状态。模型获得简短的目标、仍可复用的观测、尚待验证的问题和相关决策。待用户触发、授权或补充外部观测时，下一轮优先识别该输入并继续。
2. 证据按采集时间、对象身份、版本、观测窗口及相关变更判断适用性。用户报告环境已变化时，将受影响的证据标为待验证。过期观测可作为带时间的历史记录使用。重新使用前按当前权限复核，对撤权范围停止注入与展示诊断状态。
3. 复用已满足当前问题的观测。需要刷新时说明原因，并走新一次工具调用及授权。模型输出分别展示「已确认」「待验证」及「下一步」。没有直接证据时保留假设，说明缺少哪项观测。
4. 拒绝结果按目标和规范化操作意图随轮次保留，识别同一影响的重复提案。批准与执行继续由现有服务裁决。执行完成后单独检查工作负载状态及用户最初报告的故障。取消、重试或恢复时，对执行结果未知的操作先核对实际状态和审计。
5. 将可用的增量结果随会话保存，使用现有会话写入约束及稳定事件标识处理并发、重试和去重。页面刷新及副本切换后可续查，SSE 仅用于展示进度。旧会话缺少诊断状态时从后续实际观测增量建立。切换故障目标时重设当前调查范围，切换集群时重新绑定并授权。分叉时只接收分叉点之前仍有权使用的安全证据。

会话内调查状态随会话生命周期管理。现有跨会话长期记忆仍走人工确认与当前证据复核流程。历史观测、用户决策和审批引用均无权授权后续操作。

### 3.3 历史、压缩与分叉共用权限过滤

当前模型请求会从会话消息重建工具观测，分叉会复制截至分叉点的用户输入与最终回答。为防止旧回答带回已撤权的结论，服务端在组装模型请求（含压缩请求）、返回页面快照、重连回放、生成会话导出及创建分叉时，按当前身份复核来源范围。一次比较的结论依赖双方，任一方失权即隐藏该结论。摘要和最终回答继承所用证据的范围；混合内容仅在能可靠拆分时保留仍获授权的部分。

旧轮次缺少逐条来源时，可用可信的历史执行范围作保守上界。仅当该上界完整且当前仍获全部授权时才复用或返回正文，否则省略整条并提示“部分历史内容因权限范围无法确认而隐藏”。会话列表可见或会话当前绑定的 namespace 均不足以证明旧轮次的执行范围。过滤在服务端读取时生效，保留原有审计记录及其独立访问控制。

## 4. Secret 诊断交互

### 4.1 先查引用，再判断是否需要值

1. 使用工作负载、ConfigMap 和 Secret 元数据确认来源关系，例如 Secret 引用、环境变量映射、目标键是否存在。配置脱敏保留字段路径与能安全解析的变量名，例如 `${MAIL_PASSWORD}`。字面值与引用表达式中的敏感默认值继续遮蔽。先覆盖本场景使用的配置输出路径，并同时验证工具输出、模型输入及报告中的脱敏表现。
2. 需要判断值时，首版支持「是否非空」和「与指定的同范围配置字段是否一致」。读取请求绑定集群、namespace、Secret、键、比较对象及操作类型。平台先校验所有相关目标的访问资格，越权直接返回无权限。同一诊断动作确需多个 key 时，确认界面逐项列出，用户可以针对该次明确的读取范围作决定。
3. 用户确认后，执行边界重新校验当前权限、目标绑定、凭据与 Kubernetes RBAC，再读取所需 key 并在服务端完成判断。返回固定结果，例如一致、不一致、空、缺失或无法确认，并附来源与时间。诊断状态只保存这类最小结论以及允许保留的来源元数据。比较目标限于当前诊断中已确定的配置字段，避免形成可反复试探任意候选字符串的比较接口。结果中省去原值、片段、长度和指纹。
4. 明文确有必要时，继续使用现有 ModelOnly 路径。Admin 和 namespace 资源 read 的资格、纯报告权限规则、每次真人确认及旧 `auto` 的兼容口径沿用现行规范。ModelOnly 仅进入当前轮模型请求，聊天 SSE、报告、历史、持久化和审计保持脱敏。独立 `secret/reveal` 继续重新鉴权、禁止缓存，浏览器仅内存保留并按失焦或 60 秒规则清除。

受控判断属于 `agent.secret.access=read_on_demand` 下需要真人确认的敏感读取能力。通过工具能力声明接入现有授权与审批链路，复用底层按 key 读取门面；比较路径在执行边界直接生成结论，整个调用不构造 ModelOnly、长度或指纹。旧 `auto`、批量同意和已批准操作缓存均不能满足此次确认。非空检查分别返回“非空”“空”“缺失”或“无法确认”；比较按明确来源的字段原始字节判断，相等、缺失与无法解析分别表达。

比较对象由服务端从已观察到的工作负载配置关系中解析，绑定双方对象身份、字段路径及适用版本。只接受该关系上的字段引用，不接受聊天传入的候选值或任意同 namespace 字段。如果配置直接引用被查的 Secret/key，来源问题在元数据阶段即可回答。遇到不支持的表达式、确认期间对象被替换或版本变化导致原比较条件失效时，返回“无法确认”并说明原因；需要继续读取时按新目标重新确认。两侧分别记录实际采集版本及时间。

### 4.2 快照与复用

跨轮复用的是某次已授权观测的结论。后续需要确认当前值、观测已失效或者目标发生变化时，重新逐项确认并鉴权。候选比较对象的变化视为新请求。明确区分「配置来源一致」「值在指定时刻一致」「运行实例已加载」和「外部依赖接受凭据」这四类结论。

### 4.3 普通聊天输入的脱敏边界

平台 Chat 接收用户消息或追问补充时，在首次写入、发布事件、记录请求正文或构造模型上下文之前生成安全文本。会话消息、轮次输入、交互答复、审计、SSE、模型请求和后续导出均从安全文本取值。入口错误日志也不得记录原始正文。前端在输入处说明普通聊天会留痕，并引导用户通过受控入口核对凭据；服务端对可识别的凭据独立脱敏。任意无标识字符串的可靠识别不作为发布承诺。

带有标识的字面值应遮蔽。结构化配置中可安全解析的变量引用保留字段路径及变量名，含敏感默认值的表达式只输出可证实的引用元数据；解析失败时遮蔽整个值。

## 5. 实施顺序

1. **普通输入脱敏**。先修复已在会话导出中出现的凭据留痕，并检查首次模型请求。此项可独立交付。
2. **Pod 重启续查**。用一个实际流程接通目标、带来源的观测、等待事项、用户反馈和故障验证结果，同步完成权限过滤、存储恢复与上下文预算接入。
3. **Secret 配置核对**。接入安全引用和受控比较，将最小结论写入同一套续查状态。
4. **平台 Chat 验收**。以原 SMTP 案例重演多轮交互，核对工具调用、模型实际收到的内容和最终报告。

## 6. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| Pod 启动失败，用户下一轮补充一次重启结果 | Agent 使用仍有效的既有观测，优先查变动对象、相关事件或新日志窗口。刷新页面、上下文压缩和服务重启后仍可续查。 |
| 配置与 Secret 不一致 | 可看到必要的引用和来源。完成一次范围明确的确认后得到安全比较结果，后续追问复用快照。没有真实发信结果时，最终报告把 SMTP 失败环节保留为待验证。 |
| 审批拒绝和撤权 | 越权请求不创建审批。审批前有权限、执行前被撤权时无法读取。新读取需要新确认。续查不会向已撤权用户暴露该范围的安全比较结果，也不会自动重提已拒绝的等效写操作。 |
| 变更及故障验证 | 审批、执行、工作负载状态和原故障结果可分别追溯。中断后结果未知时先核对状态，重试不重复发起写入。 |
| 敏感数据全链路 | 用测试凭据验证诊断状态、压缩请求、SSE、日志、历史、导出和审计无明文。单独覆盖受控 ModelOnly、reveal 的现有行为，以及配置中的安全引用、敏感默认值和字面值。 |
| 版本升级 | v4.0.1 会话可加载，新轮次能建立状态，已有审批与审计记录可读。新版状态缺失时仍可进行普通 Chat。 |
| 普通输入首次分流 | 分别通过普通消息与追问答复提交带标识的测试凭据。检查首个模型请求、轮次输入、交互记录、SSE、应用日志、数据库、审计及导出，均只出现脱敏文本。 |
| 部分撤权与旧轮次 | 同一会话保留 A、B 两个范围的观测，撤销 B。检查后续模型及压缩请求、刷新、重连、导出与分叉，A 的独立观测可见，依赖 B 的结论隐藏；无法判定范围的旧回答整条隐藏。 |
| 受控比较边界 | 直接引用同一 key 时零次内容读取。比较独立字段时一次明确确认，模型和工具事件只收到结论与安全来源。缺失 key、空值、敏感默认值、对象替换或版本失效分别得到预期结果；普通批量审批不能放行。 |
| SMTP 多轮追问 | 用户补充“刚又发了一次，还是失败”。Agent 接续等待事项，优先核对该次尝试的时间窗口及错误；无相关变更时不重读 Secret。仅有 Pod 就绪、配置差异或窗口内无匹配日志时，报告仍将实际失败环节列为待验证。 |

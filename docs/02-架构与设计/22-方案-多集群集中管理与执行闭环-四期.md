# 多集群集中管理与执行闭环方案

- 版本：v1.0
- 日期：2026-11-10
- 状态：架构提案与开发计划；本轮未修改业务代码，A/B/C 真机联合验收待完成。
- 决策：ADR-052；四期 P12，紧接 P10 底座优化执行。

## 1. 目标形态

A 是平台所在集群，集中部署 Web、Backend（含 Agent Runtime）及已有数据设施。通过各自的 Kubernetes API 管理 A/B/C。B/C 首版不部署 AegisOps Agent、Operator、CRD 或业务服务；只需准备所需 RBAC 及可导入的访问凭据。

~~~mermaid
flowchart TB
  U[用户: 一个入口 / 选择目标集群] --> W
  subgraph A[集群 A: 平台部署位置]
    W[Web] --> B[Backend: API + Agent Runtime + Tools + Executor]
    B --> D[(数据库: 集群 / 加密凭据 / 授权 / 会话 / 报告)]
  end
  B --> KA[A Kubernetes API: 显式接入后管理]
  B --> KB[B Kubernetes API: B 的凭据和 RBAC]
  B --> KC[C Kubernetes API: C 的凭据和 RBAC]
~~~

A 的宿主身份不等于当前业务目标。要管理 A，优先沿用相同导入流程显式登记；不因当前 Pod 在 A 就自动把缺失或失败目标回落到 A。最小一体化模式使用完全相同的接入与执行逻辑。

平台后端到各目标 API Server 的地址、DNS、TLS/CA 与网络必须可达；不要求三集群 Pod 网络互通，也不需要服务网格。logs/exec 等使用各自 Kubernetes API 通道。网络不可达时由现场 VPN/专线等解决，首版不研发反向隧道或驻场远程 Agent。该拓扑的中心服务故障会影响所有目标，首版明确接受单中心单副本边界。

## 3. 使用与目标规则

管理员添加 B/C、选择 kubeconfig 中具体 context、连测并保存。平台按现行身份方案给用户授权到精确 ClusterID 和资源范围。用户只看到自己可用的目标；界面列表隐藏不能替代后端逐请求核权。

新建会话或发起体检时选择一个集群，后续固定到该会话/任务。切换页面选择仅影响新会话/新任务，不能迁移已有会话；恢复、刷新、历史查看均展示原集群名称与稳定 ID。权限不足、集群删除、凭据失效或不可达明确报错，不寻找其他目标继续执行。

首版每任务只操作一个集群；支持同一入口分别管理 B/C 和按集群查报告，不实现一句话跨集群写操作、批量变更事务或多集群故障联动编排。汇总列表与跨集群写执行是独立需求。

## 4. 执行与数据隔离

每次运行从已绑定 ClusterID 获取当前有效授权与对应凭据，复用已有临时 kubeconfig 或目标 REST config。禁止改全局 current-context、共享可变客户端或让模型通过 --context/--kubeconfig/--server 等参数改目标；实现时核验现有命令解析和 shell 路径的约束，缺口才补。未注册目标、空目标与无授权范围确定性拒绝。

授权按 ClusterID 精确匹配；B 中 default 命名空间的授权不能用于 C。会话、体检、报告、证据引用、审批调用、审计以及涉及资源的缓存键必须可追溯到 ClusterID；已有命名空间/资源名维度不足时补集群维度。P5 后续长期记忆检索也遵守集群和权限范围，首版不另建记忆平台。

既有审批协议继续使用，多集群不等待 P4 完整页面：提案与确认绑定原集群、身份、参数与凭据版本，确认前重验；凭据变化使旧执行授权失效，需要重新提案/确认，禁止直接套用旧批准。Secret 与命令审批规则不因多集群改变。

B 不可达不应把 C 标为不可用，不回落到宿主 A；超时/错误按目标隔离。连接测试不要求 cluster-admin，也不以无权限读取非资源健康端点直接推断所有业务 API 不可用；区分网络/TLS/认证/资源授权和可用范围。

## 5. 凭据生命周期

只导入现有支持的内嵌证书/CA/token 等便携凭据；沿用拒绝 exec/auth-provider、本地文件引用与 impersonation 的限制，不为多集群新增任意命令执行认证插件。

管理员原位更新时先校验并测试候选凭据，失败不覆盖旧配置；成功原子替换加密存储、更新版本，保留 ClusterID 和历史引用。若允许变更 API 地址，必须单独展示旧新目标并确认；首版凭据轮换默认限定原逻辑集群，不提供静默换集群入口。

令牌到期提示和重新导入属于本轮闭环；不实现通用自动续签/云厂商身份代理。撤销、删除或更新凭据后，后续请求与待审批恢复按当前版本拒绝旧身份。已发出的 Kubernetes 请求无法撤回，写入结果不明时对账，不自动重放。

## 6. 可搬运程度与来源裁决

优先复用本产品已有 internal/cluster、PlatformAccess/BoundRun、client-go、Executor 与现有 UI，比引入外部多集群框架工作量小。client-go 已提供各目标配置和客户端构造，不再包装一套通用集群 SDK。

HolmesGPT 本地 docs/installation/k9s-installation.md 展示每次调用使用独立临时 kubeconfig 的做法，可借鉴隔离用例；我方已有 ExecutionConfig + TemporaryKubeconfig，不替换为它的 shell 脚本、不复制 --raw 命令。该来源不提供可直接整体搬运的集群管理、授权与凭据轮换平台，不能描述为照搬 HolmesGPT 多集群架构。

kagent v0.10.6 保持部署模板片段参考，不搬 CRD/Controller/ADK。多集群不需要把各集群建成子 Agent；未来 B/C 网络不可直连且确有需求，再单独评估 remote executor/relay，首版不预建。

## 7. 批次与出口

P12 六项 5.00d 净工程初估，依赖 P10 验收；P12.1 复核差异后重估，实际环境准备等待另计。按“已有目标链路核验 → 执行隔离补缺 → 原位凭据更新 → UI 归属闭环 → 隔离回归 → A/B/C 联验”完成，不重复开发已落地功能。

至少验证 B/C 同 namespace、同资源名、不同内容；交替/并发 Chat 与诊断子调用；体检与报告实际来自所选目标；B 授权不通用 C；撤权/凭据更新后旧调用与旧批准失效；B 故障 C 独立可用；未知集群不回落 A；凭据替换不改历史 ID；重启后已保存会话/报告归属不变。真实联合环境验证与模拟测试分开记载，未验证不宣称多集群上线完成。

# 多集群集中管理与执行闭环方案

- 版本：v1.1
- 日期：2026-11-13
- 状态：P12.1–P12.5 的代码、界面与自动化测试已按本方案落地；P12.6 A/B/C 真机联合验收未完成，不宣称多集群上线完成。
- 决策：ADR-052；四期 P12；执行顺序以四期计划 §12 和 ADR-053 为准：P10 → P11 → P12。

## 1. 目标形态

A 是平台所在集群，集中部署 Web、Backend（含 Agent Runtime）及已有数据设施。通过各自的 Kubernetes API 管理 A/B/C。B/C 首版不部署 AegisOps Agent、Operator、CRD 或业务服务；只需准备所需 RBAC 及可导入的访问凭据。

~~~mermaid
flowchart TB
  U[用户: 一个入口 / 选择目标集群] --> W
  subgraph A[集群 A: 平台部署位置]
    W[Web] --> B[Backend: API + Agent Runtime + Tools + Executor]
    B --> D[(数据库: 集群 / 加密凭据 / 授权 / 会话 / 报告)]
  end
  B --> KA[A Kubernetes API: 显式接入后管理]
  B --> KB[B Kubernetes API: B 的凭据和 RBAC]
  B --> KC[C Kubernetes API: C 的凭据和 RBAC]
~~~

A 的宿主身份不等于当前业务目标。要管理 A，优先沿用相同导入流程显式登记；不因当前 Pod 在 A 就自动把缺失或失败目标回落到 A。最小一体化模式使用完全相同的接入与执行逻辑。

平台后端到各目标 API Server 的地址、DNS、TLS/CA 与网络必须可达；不要求三集群 Pod 网络互通，也不需要服务网格。logs/exec 等使用各自 Kubernetes API 通道。网络不可达时由现场 VPN/专线等解决，首版不研发反向隧道或驻场远程 Agent。该拓扑的中心服务故障会影响所有目标，首版明确接受单中心单副本边界。

## 3. 使用与目标规则

管理员添加 B/C、选择 kubeconfig 中具体 context、连测并保存。平台按现行身份方案给用户授权到精确 ClusterID 和资源范围。用户只看到自己可用的目标；界面列表隐藏不能替代后端逐请求核权。

新建会话或发起体检时选择一个集群，后续固定到该会话/任务。切换页面选择仅影响新会话/新任务，不能迁移已有会话；恢复、刷新、历史查看均展示原集群名称与稳定 ID。权限不足、集群删除、凭据失效或不可达明确报错，不寻找其他目标继续执行。

首版每任务只操作一个集群；支持同一入口分别管理 B/C 和按集群查报告，不实现一句话跨集群写操作、批量变更事务或多集群故障联动编排。汇总列表与跨集群写执行是独立需求。

## 4. 执行与数据隔离

每次运行从已绑定 ClusterID 获取当前有效授权与对应凭据，复用已有临时 kubeconfig 或目标 REST config。禁止改全局 current-context、共享可变客户端或让模型通过 --context/--kubeconfig/--server 等参数改目标；实现时核验现有命令解析和 shell 路径的约束，缺口才补。未注册目标、空目标与无授权范围确定性拒绝。

授权按 ClusterID 精确匹配；B 中 default 命名空间的授权不能用于 C。会话、体检、报告、证据引用、审批调用、审计以及涉及资源的缓存键必须可追溯到 ClusterID；已有命名空间/资源名维度不足时补集群维度。P5 后续长期记忆检索也遵守集群和权限范围，首版不另建记忆平台。

既有审批协议继续使用，多集群不等待 P4 完整页面：提案与确认绑定原集群、身份、参数与凭据版本，确认前重验；凭据变化使旧执行授权失效，需要重新提案/确认，禁止直接套用旧批准。Secret 与命令审批规则不因多集群改变。

B 不可达不应把 C 标为不可用，不回落到宿主 A；超时/错误按目标隔离。连接测试不要求 cluster-admin，也不以无权限读取非资源健康端点直接推断所有业务 API 不可用；区分网络/TLS/认证/资源授权和可用范围。

## 5. 凭据生命周期

只导入现有支持的内嵌证书/CA/token 等便携凭据；沿用拒绝 exec/auth-provider、本地文件引用与 impersonation 的限制，不为多集群新增任意命令执行认证插件。

管理员原位更新时先校验并测试候选凭据，失败不覆盖旧配置；成功原子替换加密存储、更新版本，保留 ClusterID 和历史引用。若允许变更 API 地址，必须单独展示旧新目标并确认；首版凭据轮换默认限定原逻辑集群，不提供静默换集群入口。

令牌到期提示和重新导入属于本轮闭环；不实现通用自动续签/云厂商身份代理。撤销、删除或更新凭据后，后续请求与待审批恢复按当前版本拒绝旧身份。已发出的 Kubernetes 请求无法撤回，写入结果不明时对账，不自动重放。

## 6. 可搬运程度与来源裁决

优先复用本产品已有 internal/cluster、PlatformAccess/BoundRun、client-go、Executor 与现有 UI，比引入外部多集群框架工作量小。client-go 已提供各目标配置和客户端构造，不再包装一套通用集群 SDK。

HolmesGPT 本地 docs/installation/k9s-installation.md 展示每次调用使用独立临时 kubeconfig 的做法，可借鉴隔离用例；我方已有 ExecutionConfig + TemporaryKubeconfig，不替换为它的 shell 脚本、不复制 --raw 命令。该来源不提供可直接整体搬运的集群管理、授权与凭据轮换平台，不能描述为照搬 HolmesGPT 多集群架构。

kagent v0.10.6 保持部署模板片段参考，不搬 CRD/Controller/ADK。多集群不需要把各集群建成子 Agent；未来 B/C 网络不可直连且确有需求，再单独评估 remote executor/relay，首版不预建。

## 7. 批次与出口

P12 原六项 5.00d 为历史净工程初估，不覆盖本版新增的完整能力对等及界面验收；P12.1 核对后重新估算，环境准备和人工等待另计。执行顺序和门禁以四期计划 §12 为准。按“已有目标链路核验 → 执行隔离补缺 → 原位凭据更新 → UI 归属闭环 → 隔离回归 → A/B/C 联验”完成，不重复开发已落地功能。

至少验证 B/C 同 namespace、同资源名、不同内容；交替/并发 Chat 与诊断子调用；体检与报告实际来自所选目标；B 授权不通用 C；撤权/凭据更新后旧调用与旧批准失效；B 故障 C 独立可用；未知集群不回落 A；凭据替换不改历史 ID；重启后已保存会话/报告归属不变。真实联合环境验证与模拟测试分开记载，未验证不宣称多集群上线完成。

## 8. Agent 能力一致性契约（v1.1）

同一平台配置下，A/B/C 共用 Agent Runtime、模型、工具注册、Skill、诊断、审批和执行策略；选择集群只改变可信目标连接和相应授权，不改变产品提供的能力。相同授权、RBAC、API 能力及前置条件下，应提供相同操作和交互；各集群资源、版本、权限与可达性差异可以导致结果不同，必须明确说明原因，不能静默降级、换目标或编造结果。

| 能力 | 目标绑定与验收 |
| --- | --- |
| 问诊、上下文、模型、Skill | 同一套能力；会话和上下文固定集群，切换进入新会话或该集群已有会话 |
| 结构化读、日志、事件、诊断子调用和体检 | 统一工具和规则，所有 client 与子调用使用绑定目标，证据和报告标注真实 ClusterID 与覆盖范围 |
| kubectl、受控只读组合、写入及写后验证 | 相同权限和审批策略；每一调用及验证均绑定目标，实际 API 目标与审计一致 |
| 创建、Secret 专用通道、审批 | 原有开关和安全规则不变；目标、身份、参数和凭据版本绑定，轮换或撤权使旧批准失效 |

P12.1 必须列出已注册能力、各入口和真实执行链，逐项记录已验证/缺口/不适用。以服务端可信绑定贯穿会话、工具、Reader、Executor、诊断子调用、审批、写后验证与产物；不能用前端选择或模型参数作为安全边界。历史数据按可信 ClusterID 和实际 coverage 校验，缺失时按身份方案治理，不猜测归属。

### 8.1 复杂 shell 的目标边界

真人审批不替代目标隔离。单靠环境变量或普通 kubectl 参数检查不能证明任意 shell 的目标：P12.1/12.2 须审查 shell 能力、凭据暴露、目标覆盖及实际隔离机制，并给出可复现测试。仅在能证明绑定目标和授权边界时允许该路径；无法证明时在多集群平台模式拒绝该类执行并明确提示，或先实现经过审查的隔离机制。保留已验证只读组合的受控 argv 通道和现有真人审批要求；不得扩大 shell 或 Secret 权限。

### 8.2 凭据与集群身份

原位轮换先验证候选并原子替换；失败保留旧值。集群名称或 API 地址相同不足以证明是同一集群；需设计可验证的身份依据及不可验证时的明确处理，不得静默把另一集群继承为原 ClusterID。若无法建立可信一致性，则阻止原位替换并走单独接入及人工核对；旧会话、报告与审批不能自动迁移。已发出请求无法撤销，结果不明时对账，不自动重放。

## 9. 前端多集群工作台

集群页由单一“当前集群”展示调整为工作台：顶部显示有明确来源及检查时间的集群总数、最近连测成功/失败/未检查统计；主体为可搜索的列表，展示名称、Context、最近检查结果与时间、可获得的版本和操作。未知、未检查、过期结果不得显示为实时健康；连接成功不等于具备全部业务权限。首版支持名称/Context 搜索及状态筛选，不要求拓扑大屏或卡片视图。数量增长时再按实际接口补分页。

点击行打开详情抽屉，展示可信元数据、检查结果及原因、当前用户授权范围；管理员可进行连测、更新凭据和删除。可见字段和操作按权限过滤，后端逐次核权。列表提供问诊、体检、报告入口：分别新建绑定目标会话、预选目标体检、按目标筛选报告；无权或不可达时解释原因，历史报告仍按现有授权独立判断。

接入改为按钮打开抽屉：导入 kubeconfig → 选择明确 context 与名称 → 连测 → 保存；不缓存或展示凭据明文。测试结果区分网络/TLS、认证与资源权限（仅在有证据时），不把连测成功说成具备所有权限。凭据更新遵守 §8.2。

聊天页持续显示**当前会话绑定的集群**，并将新会话目标选择与当前会话区分；切换操作明确创建新会话或打开该集群已有会话，不改变原会话、上下文及待审批操作。历史列表显示集群归属；审批与写操作确认显示集群及资源目标。目标失效显示明确状态，不回落。报告及体检入口继续展示真实目标和覆盖范围。

## 10. 对等与隔离验收矩阵

- B/C 使用同 namespace、同名资源、不同标识和故障；分别验证结构化读取、日志、事件、诊断、kubectl、Skill、创建、体检、报告及实际 API 请求目标。相同前置条件核对工具集合和行为；不适用项须记录原因。
- 在相同授权下分别验证需真人审批的写操作、确认目标与写后验证；验证 Secret 现行 always/auto 语义，旧批准不能跨集群或跨凭据版本使用。复杂 shell 分别验证可证明的目标约束和无法证明时拒绝。
- B/C 交替及并发 Chat，检查 client、临时文件、上下文、证据、缓存与报告不串；空/未知/删除目标不回落 A。
- 撤权、认证会话失效、凭据轮换、B 不可达及请求结果不明；检查旧调用/审批失效、C 不受影响、无自动重放。
- 覆盖不同 RBAC、缺 CRD、版本及网络差异，呈现真实原因；历史数据、报告下载和权限撤销按 coverage 校验。
- UI 验证搜索、状态及过期时间、权限过滤、接入、目标切换、新旧会话归属、审批目标、体检和报告入口。
- 自动化与 A/B/C 真机验收分别记录；真实环境未通过不能宣称完成。P12.1 输出链路和能力清单后重估，P12.5 通过自动化，P12.6 完成人工联合验收。

# AegisOps 审计中心设计

状态：2026-11-18 已实现（P4.7/P4.8/P4.9）。实现事实见 §6。

## 1. 产品职责

审计中心是管理员的只读追溯入口。管理员可以按时间、操作者、集群和事件类型检索平台操作，从一条记录看到谁提出操作、谁确认、实际发出了什么操作、执行结果以及验证结果。审批作为审计事件展示，操作确认仍在 Chat 中完成。

治理菜单只保留「审计中心」。首版交付列表、筛选、详情和关联时间线。普通用户通过有权访问的原 Chat 查看自己的操作上下文。

## 2. 页面与查询

列表默认按时间倒序，显示时间、操作者、事件类型、集群、操作对象和结果。支持时间范围、事件类型、操作者、集群、结果和会话筛选。事件覆盖登录、会话、人工确认、会话授权、工具执行、Kubernetes 访问与变更，以及已有记录的配置、集群和 Skill 管理操作。

详情展示结构化摘要和关联事件。一次变更按已记录的事实展示提议、确认、请求授权、执行结果、后续验证。需要查看原上下文时提供会话入口，跳转后沿用 Chat 的访问校验。执行结果未知、未执行、未验证和历史字段未记录分别展示。

后端提供 `GET /api/v1/audit/events` 与 `GET /api/v1/audit/events/{id}`。列表由数据库过滤，按 `timestamp DESC, id DESC` 使用游标分页，默认 50 条、上限 100 条。详情返回当前事件和按明确关联键查询的有界时间线。列表和详情均要求已登录的 Admin 及现有 `audit.read` 权限，前端菜单同步使用权限判断。

## 3. 数据来源与关联

平台数据库中的 `AuditStore` 是页面查询来源。复用现有审计写入和事件分类，扩展有界查询及必要索引。保留已有存量记录；老数据缺少关联字段时显示「未记录」。底层已有会话、回合、步骤、用户、集群和审批 ID 等字段，实施时核对实际写入，按需补齐以下信息。

| 事件 | 必要信息与判定 |
| --- | --- |
| 操作提议与确认 | 发起者、实际确认者、目标、风险、决定、时间；通过审批或 Interaction ID 关联 |
| Kubernetes 请求授权 | 绑定集群、请求动作、授权结论；关联到对应工具调用。Gateway 放行只表示请求通过授权 |
| 执行 | 工具、目标和终态；通过会话、回合、工具调用 ID 或已有可靠的步骤 ID 关联 |
| 验证 | 验证对象、检查结果、时间和对应执行记录；仅在确有验证事件时展示 |

审批结果、执行结果和验证结果各自取实际事件。不同结论的记录即使相邻也按各自的关联 ID 展示。同一动作经过不同层时，保留各层的独立事实；同一事实现有重复写入时按稳定事件标识归并展示。

## 4. 安全与可靠性

查询接口用字段白名单返回脱敏摘要，避免直接透传存储层 `Payload`、原始工具参数和终端输出。Secret 值、kubeconfig、API 密钥和短期通道凭据在写入、查询与日志出口均按现有红线处理。

沿用关键动作已有的审计失败门禁。现有部分观察事件落库失败会告警，补齐关联时逐条验证实际写入链。缺失的结果显示为未记录或未知。查询故障在审计页面反馈，审计读取与 Chat 运行独立。

## 5. 实施与验收

1. 用真实的确认、拒绝、执行和验证路径核对事件与字段，补齐关键关联。复用现有存储，验证 SQLite 和 MySQL 迁移兼容。
2. 实现只读查询 API、复合筛选、游标分页和详情关联。验证普通用户直调列表和详情会被拒绝，分页在相同时间戳和并发插入场景仍按确定顺序返回。
3. 实现审计页面并收敛治理入口。以一次真实 Chat 变更验收确认者、操作目标、执行和验证可追溯，同时覆盖拒绝、授权拒绝、已批准但执行失败、执行结果未知、历史信息缺失和敏感信息脱敏。

## 6. 实现记录（2026-11-18）

- **后端**：`internal/store/audit_query.go` 提供 `ListFiltered`（过滤与 keyset 游标全部下推 SQL）与 `Timeline`（只按 approval/grant/request/turn 显式关联键取同链事件，全部缺失时才退回会话级并有界）；schema v14 补 `(timestamp,id)`、`cluster_id`、`approval_id`、`request_id` 索引。
- **服务层**：`internal/service/audit_query.go` 的 `AuditQueryService` 只投影字段白名单，存储层 `payload` 永不进入响应；操作者显示名由用户表解析，账号已删则退回用户 ID；游标编码只在服务层，前端视为不透明串。
- **API**：`GET /api/v1/audit/events`（默认 50、上限 100，`from/to/eventType/userId/clusterId/sessionId/status/action/limit/cursor`）与 `GET /api/v1/audit/events/{id}`；两条路由在网关登记 `audit.read`，未登录 401、无权限 403、未装配 Store 501、非法参数 400、事件不存在 404。
- **前端**：`web/src/api/audit.ts` + `web/src/views/audit/AuditView.vue`（筛选、加载更多、详情抽屉、关联时间线、原会话入口）。侧栏「审计」改为「审计中心」；`/app/approval` 路由与独立审批页删除，审批决定作为审计事件查询，确认动作仍在 Chat。
- **联验**：`go test ./...`、`go vet ./...`、`npm run test/typecheck/lint/build` 全绿；服务端用例覆盖越权、游标翻页、时间线与敏感值不出响应，前端用例覆盖列表/详情/空态与会话直达。

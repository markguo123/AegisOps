## 2. 配置中心与管理入口

| 页面 | 可编辑项及权威源 | 保存后实际行为 |
| --- | --- | --- |
| 配置中心 → 记忆 | memory.enabled、memory.max_items，落 settings | enabled 默认关，控制建议、创建、编辑和逐次模型请求召回。max_items 默认 200，允许 1–1000，表示每位用户最多保有的未到期个人诊断记忆。 |
| Chat → 诊断记忆 | 本人记忆及来源关系，落 memories | 查看、保存、编辑、到期、遗忘和查看引用。UI 显示集群名称，记录绑定集群 ID。 |
| 配置中心 → 保留 | 各 cluster_id 与 kind 的保留天数、最低保留份数、执行周期、策略版本和启停，统一落 report_retention_policies | 预览、确认启用、停用及查看运行历史。每条策略只有一个启停状态。周期可选 15、30、60、360 或 1440 分钟，默认 60。 |
| 智能体检中心 → 报告保留 | 仅平台管理员可见的快捷入口，跳转到配置中心的保留页，可带入当前筛选的集群和报告类型 | 普通报告用户看不到入口，直接访问保留策略页或接口也会被拒绝。 |

- 记忆所有权固定为个人，诊断经验必绑集群、主 namespace 和工作负载，可带相关 namespace。移除 scope_user、scope_namespace、scope_cluster 的可编辑配置，页面用业务文字说明隔离规则。
- 移除 retention.enabled、default_retention_days、default_cleanup_mode 可编辑入口。停止接收这些旧键的普通写入，返回可理解的替代入口。数据库历史值不作为运行默认，也不在迁移中转换成删除授权。
- 报告策略配置、预览和运行历史仅授权平台管理员。保持配置中心现有的身份、CSRF 和审计路径，服务端逐操作校验，普通 settings.write 无法间接启动自动删除。配置和审计原子提交，老页面提交已退役字段时必须明确报错。通用配置导入不得激活保留。
- 每条策略预览后由管理员明确启用。调度器只依据该策略的启停、版本、运行周期和候选规则执行。停用后可继续查看和预览，重新启用须再次确认。手动删除维持原有权限规则。
- 页面使用中文业务标签和准确的生效说明。禁止展示「P5.2 消费」「P5.4 消费」、可保存但无效果的开关，以及由多个页面分别写同一语义的配置。

## 3. 故障诊断长期记忆

### 3.1 用户流程

从同一故障验证过的排查方法产生可复用草稿。例如 payment-api 发布期间返回 502，已通过对齐 payment 中旧 Pod 退出时间与 edge-system 网关报错定位问题。草稿只保留如何比对与适用范围。下一次若 502 早于此次发布，Agent 应以当前时间线继续排查。

1. 用户在 Chat 点「记住排查经验」可手工新建。用户说「记住刚才的排查方法」时优先复用本轮草稿；没有可复用草稿时，从本人当前会话已完成的问答及可安全使用的证据摘要请求一次提炼。提炼无 Kubernetes 工具权限。信息不足时提示补充范围或手工填写。
2. Agent 只在有已核实、可复用的排查方法时，在成功结束的结论下提供一次「保留这条排查经验」。进行中、失败、取消、只有常规检查或关键证据不足的轮次均不提示。Secret 诊断轮禁用自动提炼和预填。
3. 展示当前集群名、主 namespace、关联 namespace、工作负载和经验文本。用户可编辑，点确认才保存；关闭、SSE 重连、重试均不能隐式提交。未证实的范围必须由用户补全，保存仍要通过服务端授权复核。
4. 有来源的条目可跳到已完成的本人会话及轮次。历史条目无来源时显示「手工记录」或「来源未记录」。来源删除时解除链接，已确认的独立记忆继续有效；来源权限不足时隐藏跳转，不回显其标识。
5. 最近会话旁展示本轮实际引用的记忆。历史引用仅保存条目 ID，展开时按当前权限解析，遗忘、撤权或过期后显示不可用。过期条目在个人管理中可遗忘，普通编辑不能隐式恢复已过期记录，可根据仍适用的原经验新建一条，经用户确认及权限和容量检查。

### 3.2 查询、容量和并发

- 继续采用稳定 owner、cluster_id、主 namespace 和工作负载。补齐可空的来源 session_id、turn_id、到期和版本等可查询元数据、按所有者分页索引、按目标召回索引。迁移保留已确认的 v4.0.0 条目、原 ID 与期限，历史来源缺失留空。没有所有者或无法确认的旧行不得召回。
- 列表以稳定游标分页，撤权后的本人条目仅显示不可用状态及可执行的遗忘操作，不暴露原范围或正文。召回在数据库先按本人、目标和有效期过滤，不从全局前 200 条截取。编辑校验 owner、版本和新旧范围，冲突返回 409。遗忘按 owner 条件执行并支持安全重试。
- 新建和降低限额均有明确语义。按用户事务串行化容量变化，在同一事务内计数并写入，达到上限拒绝新增并提示整理。降低额度保留现有条目，仍可编辑和遗忘，直到低于上限才允许新增。过期记录不占未到期限额，列表仍可管理。保存按 owner 与请求幂等键去重，同一请求原样重放成功，键复用但内容变化返回冲突。
- 允许运行中的旧条目继续以当前字段读取。v4.0.0 已保存的合法 max_items 值沿用，按新界面明确展示为每位用户额度并支持上述降额语义。超过新上限的历史配置按 1000 生效并提示管理员，保留所有现存条目。默认、范围、显示和事务校验共享同一配置定义。

### 3.3 召回、证据和敏感数据

- 每次准备模型请求时重新检查总开关、用户、当前绑定集群、目标、有效期及当前轮覆盖范围。命中以完整工作负载为基础，故障词只用于排序。主 namespace 不明确且出现多个可能目标时跳过并按普通问诊处理。对主及全部相关 namespace 逐一校验当前读取权限，纯报告授权不足以召回。
- 记忆作为不可信历史参考，仅临时注入本轮模型请求。保留与当次上下文预算相容的少量条目，裁剪后展示实际引用。Chat 历史输入、压缩、SSE 正文、审计不得复制注入的原始记忆块。审计记录保存、编辑、遗忘和引用的主体、条目 ID、结果以及可用的轮次关联。
- 模型先使用当前有权读取的证据复核，不得把历史结论当成当前事实。普通只读检查走现有授权路径。任何写操作和 Secret 按需读取各走本轮授权与相应真人确认，旧批准不可复用，执行边界重新校验权限。
- 提炼入口只接收安全的问答和结构化证据摘要。禁止读取 ModelOnly、Secret reveal、原始日志、工具结果与附件。模型提议的作用域必须与来源轮次已验证的目标对应，来源和权限由服务端核对。草稿和手工正文继续做敏感检测，识别到凭据时拒绝且错误不回显其值。配置读取或鉴权失败时跳过召回和建议。

## 4. 报告到期清理

### 4.1 候选规则与启用流程

- 策略以稳定 cluster_id 与 report kind 唯一定位。D 为保留天数，N 为最低保留份数，均为正整数。固定数据库 UTC 时刻 T，按 created_at DESC、id DESC 排序。某报告仅在 created_at 严格早于 T 减 D 天、排名大于 N，且拥有成功结束的 Web 扫描持久标记时可删。最近 N 份按组合内全部报告计数。当前策略对缺少成功标记的存量行、活动扫描、失败或取消扫描、缺集群或未知报告类型均不会执行删除。
- 预览与执行共用候选规则。预览显示集群名称和类型、跨用户范围、计算时刻、总量、按期限或份数保护数、终态未知的排除数和预计删除数。预览不改报告、引用或生效策略。
- 服务端签发可由所有副本验证的短效、一次性预览凭据。持久化保存凭据摘要，绑定管理员、集群、类型、D、N、执行周期、预览时刻、候选集合摘要及当前策略版本，有效期十分钟。确认时在事务内核对身份、版本和参数，以预览时刻复算候选集合摘要，原子消耗凭据并启用新版本。超时、重复使用、改配置、范围不符或当前候选变化均返回冲突并提示重新预览。停用无需预览。
- 策略变更只影响后续运行。周期改变按当前数据库时间重算下一运行时刻，已运行实例不得借旧周期继续提交。暂停期间无补跑风暴，恢复后从新调度窗口开始。

### 4.2 多副本、引用和可追溯性

1. 在数据库持久化 run 与明细。每个策略版本与调度窗口只创建一个 run，以数据库时钟及唯一约束认领。短租约和递增代次用于接管，崩溃后新实例继续同一个 run，旧代次无权提交。
2. 候选按稳定顺序分批，每批至多 200 条。保留固定 T 和候选游标。单项事务锁定并检查策略启停、策略版本、run 代次和报告组合，复核报告身份、终态、年龄和当前最近 N 排名。人工删除与自动删除共享组合锁。锁顺序在策略改动、人工删除和定时执行路径统一。策略停用提交成功后，后续删除事务必须看到停用，已提交的删除按审计追溯。
3. 删业务行、释放引用、写删除明细及审计同事务提交。条件删除未命中时不扣引用。对象账本已缺失按方案 15 现有语义处理并记录。后台不直接删对象，物理回收由已有 blob GC 在宽限期后完成。
4. 明细按 run_id 与 report_id 唯一，重试不会重复扣减。持久化删除、跳过和错误情况后推进游标，暂时性故障有限退避，单项永久失败记录原因并继续。运行历史展示待执行、运行中、完成、部分失败、失败和停止状态，以及处理数量、失败原因与审计链接。策略启停、配置改动、批次与删除记录可关联到同一个范围和版本。
5. 系统仅通过管理员的保留配置自动清理平台报告。调度无虚拟管理员身份，不调用人工删除 HTTP 路由，也不提供 Kubernetes 变更通道。

## 5. v4.0.0 升级与回退

| 升级前状态 | 升级后行为 |
| --- | --- |
| 从未在报告保留页启用策略，旧 retention.enabled 为任意值 | 没有启用策略，因此不会自动删除。旧预留配置不生成策略。 |
| 已在 v4.0.0 报告页明确启用至少一条有效策略 | 沿用该策略的启用状态、范围、D/N 与小时周期，保留下一次运行时刻与历史运行数据。未知终态报告仍受保护。 |
| 旧策略已停用，或对应集群已注销、类型未知 | 保持停用或无效，页面说明原因。 |
| 已有个人记忆和 memory.enabled | 保留记录和启用状态。部署后可以分页管理，旧记录没有来源的无需补造。 |

迁移必须幂等，重启时沿用实际策略表中已持久化的启停状态。采用新增字段和表的兼容迁移，发布时先停止旧 worker 或确保旧副本退出，再启动新版调度器，避免旧副本忽略新版策略版本和运行周期。若回退到 v4.0.0，先停用实际报告策略并确认无在途执行，再回退二进制。回退不恢复已删除报告。

## 6. 开发、验证和发布门禁

| 交付步骤 | 必须通过的检查 |
| --- | --- |
| 配置中心和 API | 每个可编辑项都有运行时测试。保存 memory.enabled 后验证建议、创建、编辑和下一次召回变化。调整 max_items 后验证并发新增和降额。保存保留周期后验证下一执行时间。停用单条策略，在下一次调度与双副本竞争中验证该范围零新删除，其他已启用策略继续按期执行。普通报告用户看不到报告页的策略入口，直接访问保留页或策略 API 被拒绝。普通 settings.write 用户无法修改保留策略。 |
| Chat 记忆 | 手工创建、主动说记住、结论建议、取消、确认保存、编辑、过期、遗忘、来源跳转、分页、幂等和并发冲突均可验收。新会话召回成功，另一用户、另一同名 namespace 的集群、撤权和过期均不召回。用哨兵值验证秘密不会流入候选、记忆、SSE、审计或历史。 |
| 报告保留 | 真 MySQL 验证 D/N 边界、同时间排序、终态保护、过期或跨管理员预览凭据、同组合策略并发编辑、双实例接管、人工删除竞争、对象共享、GC 已清账、停用后提交边界和失败历史。 |
| 正式版升级 | 从带真实形态存量数据的 v4.0.0 升级，分别用旧键为 true 且无策略、已有启用策略、有停用策略的三种样本验收。核对配置页、实际策略、报告行数、对象引用、审计和已有记忆。 |
| 发布门禁 | 执行 go test ./...、go vet ./...、前端类型检查与相关测试。独立环境执行[真机验收](../04-项目管理与规范/P5-真机验收步骤.md)，覆盖真实浏览器、模型、MySQL、对象存储和双副本。配置文档、API 文档、PRD 和开发计划核对同一生效口径，附验证结果后才可标记 P5 完成。 |

开发顺序按配置契约和升级迁移、记忆闭环、保留闭环、真机与发布验收执行。无需新增可保存的预留项，也不以计划编号或配置表结构代替实际生效验证。

# P5 故障诊断长期记忆与数据保留

2026-11-20 · 架构评审稿 v1.0 · 供排期和开发评审使用

## 1. 产品目标与交付边界

故障诊断需要跨会话保留的是用户验证过的排查经验。例如，支付服务出现 502 时，可以对齐业务 namespace 的 Pod 退出时间和网关 namespace 的报错时间。下一次问诊应能想起这个方法，并重新采集本次证据。历史根因、旧审批和上一次看到的资源状态均无当前效力。

首版交付两条独立路径。平台 Chat 提供个人诊断记忆，平台管理面提供报告到期清理。两者分别发布、分别启停。终端直用模式保持现有本地工作流。团队知识共享、自动从整段对话提炼经验、通用归档恢复，以及审计、会话、凭据等数据的自动清理留待专项评审。配置已暴露某项能力不能作为上线依据。

## 2. 从一次问诊到下一次问诊

1. 用户在 Chat 点击“记住排查经验”，或明确说“记住这个排查方法”。自然语言只打开编辑卡；卡片由用户填写或从本人明确选中的安全用户文本预填。模型和工具没有后台写入接口。
2. 卡片显示将长期保存的文字、适用服务、集群、涉及的全部 namespace，以及“匹配时会发送给当前对话所选模型”。用户确认后服务端重新校验并保存。取消、停止回答、刷新或 SSE 重连都不能隐式提交。
3. 新会话中，服务端从已绑定的目标与本轮用户输入确定匹配条件。例如用户说“payment-api 又报 502”，集群已选定且作用域匹配时，可召回上面的经验。目标不明确时先询问，或按普通问诊继续。授权通过只代表可见，相关性另行判断。
4. Chat 在本轮回答旁显示“参考了 1 条个人经验”，允许查看或纠正。Agent 先用本次证据验证线索。若 502 早于发布时间，应指出时间线冲突，并沿新证据继续排查。
5. 用户在“我的诊断记忆”查看、修改、遗忘或设定到期时间。显式遗忘提交后，后续模型请求不可再从该条记录取值。已经发送的请求及已生成的历史回答按其原有生命周期处理，页面应说明这一边界。

## 3. Memory 的数据、授权与模型边界

**所有权与适用范围。** 所有记录必须有 owner，由登录身份写入。个人全局范围只接受与环境无关的展示偏好，采用枚举字段（例如先给结论）。诊断经验必须绑定稳定 cluster_id、主 namespace 或明确的集群级范围，可附加涉及的 namespace 集合、工作负载名称和故障关键词。跨 namespace 示例应同时绑定 payment 和 edge-system。保存卡要求用户确认完整范围；不得用模型猜出的范围作为授权依据。跨集群拆分为独立记录。

**读写顺序。** 数据库先按 owner、状态、有效期、目标范围过滤，再复核该用户对每个绑定范围的当前读取授权。绑定整个集群须有对应集群范围读取资格。纯报告授权不能满足诊断记忆读取。列表、详情、编辑、来源跳转及召回各自复核；越权 ID 与缺失 ID 返回同形 404。来源会话单独检查归属。撤权后允许用户通过仅含本人条目标识与创建时间的管理视图执行遗忘，不回显正文、目标或来源。集群注销或绑定失效后停止召回。配置关闭后停写、停召回，保留个人删除入口。

**存储契约。** 扩展现有 memories 行，增加类型、主目标、匹配词、可空来源 session/turn、expires_at、版本和确认状态；涉及的额外 namespace 用关联表保存，与主体同事务更新。保存按 owner 与请求幂等键去重，重复请求不得覆盖另一份内容。更新和删除使用 owner 与版本条件，版本冲突返回 409。范围变更重新确认。范围限额在事务内校验，达到上限提示用户整理。旧行缺 owner、授权范围或用户确认来源时默认不可召回。现有 MemoryStore.List 全量查询和仅按 id 更新的接口不能用于用户请求路径。索引至少覆盖 owner、cluster_id、主 namespace；按真实查询计划核对。

**召回与注入。** 首版用结构化目标和词匹配，无需向量服务。按工作负载精确匹配、故障词命中数、最近修改时间和 ID 稳定排序。环境经验必须命中主目标及至少一个工作负载或故障词；个人展示偏好单独合并。建议每轮最多 3 条、正文每条 500 字、总注入上限 800 tokens；上下文紧张先裁掉记忆。每次组装模型请求时重新解析有效 ID，仅放在标记为历史参考数据的临时上下文内。禁入系统指令、持久化消息和会话压缩输入；工具循环、停止后续聊、切换模型均使用同一装配路径。召回超时或鉴权故障时跳过记忆，继续普通问诊。

**来源与敏感信息。** 不接受工具原始输出、日志、事件、附件、Secret reveal、ModelOnly 或任意模型回答作为自动写入源。用户手工撰写的正文仍按不可信文本处理，服务端限制长度、校验格式，复用脱敏检测并拒收识别出的凭据、kubeconfig、私钥等，错误不回显命中值。自由文本检测无法证明任意字符串均非秘密；Secret 诊断轮禁用从对话预填，禁止将模型请求或工具响应交给候选生成器。记忆不能触发工具、写授权或 Secret 同意。工具即使因记忆被建议调用，也必须走正常授权路径。

**接口与可观察性。** 建议个人资源为 GET/POST /api/v1/me/memories 和 GET/PATCH/DELETE /api/v1/me/memories/{id}。服务端忽略客户端身份声明，来源 ID 必须与本人会话及轮次匹配。召回只走服务内部接口。SSE 只传本轮引用 ID，历史回看按当前权限解析，缺失时显示“已不可用”。审计保存动作、主体、条目标识、结果及关联轮次，不保存记忆正文、匹配词或模型提示。删除来源会话后解除来源链接；用户主动另存的记忆独立保留，保存时说明。

## 4. 报告 Retention 的策略与执行契约

**范围与默认值。** 首版管理员按稳定 cluster_id 和报告 kind 配置策略，覆盖该组合下各 owner 的报告；页面明确展示跨用户影响。无集群归属、kind 未知或无法识别终态的产物默认排除。只处理已完成产物；有活动任务依赖时跳过。旧配置中的 enabled、默认 90 天和 archive 只作为迁移展示值。新策略初始关闭，必须预览并显式激活。首版仅支持删除业务引用；请求 archive 应返回明确的能力校验错误。

**选择规则。** 每次运行固定数据库 UTC 时间 T。某组合内按 created_at 降序、id 降序排序，最近 N 份优先保护，只有 created_at 严格早于 T 减 D 天且排名大于 N 的记录可删。D、N 均为正整数，零值拒绝。例：保留 30 天且至少 5 份，即使全部超过 30 天，也保住最新 5 份。预览展示范围、总量、保护数、预计删除数、少量样例与计算时刻；报告正文不可下载不妨碍候选判定。此处 N 是保底数，旧 max_count 是上限语义，迁移不得直接映射。

**配置与权限。** settings 负责调度总开关和周期，类型策略表负责每一组合的 D、N、启用状态和版本。增加唯一组合约束。旧默认键从可执行表单退出，避免出现两个可写来源。首版策略管理、预览和运行历史仅向平台管理员开放；服务端逐路由检查，普通 settings.write 不能间接激活删除。管理员保存草稿后，预览取得绑定策略版本、范围及有效期的服务端凭据，激活时重新校验。后续周期按已激活规则运行，预览数字是当时估算。修改策略产生新版本，重新预览激活；关闭总开关或停用策略立即阻止后续删除事务。

**运行一致性。**

1. 每个策略版本和计划时间窗有唯一 run；多实例通过数据库认领，租约带递增代次。记录固定 T、分页游标、状态及计数。重启后接管同一 run，旧持有者失去提交资格。
2. 按稳定键分页，单批至多 200 个候选。每项独立事务，先校验租约代次、总开关、策略版本及有效状态，再核对报告当前归属、年龄、活动依赖和最近 N 保护。预览与执行共用候选判定。涉及同组合的自动清理与人工删除须共用数据库组合锁，按统一顺序取锁后重新计算排名。人工删除仍尊重原有权限与用户选择。此保底约束仅约束自动删除。
3. 共用报告删除的事务原语。条件删除命中一行才释放对应 blob_key；沿用对象账本已缺失或计数已归零时的既有处置。禁止 worker 构造虚拟管理员、调用下载接口或直接操作桶。审计与运行明细必须随删除同事务持久化，可用事务内待投递记录向现有审计服务幂等投递。提交失败则整项回滚，不能出现已删除却无法追溯。
4. 明细以 run_id + report_id 唯一。重复处理已提交项读取既有结果，缺行记为跳过。游标仅在该页处理结果持久化后推进；可重试故障有限退避，永久失败记原因并继续。策略变更、总开关关闭或租约失效时结束当前批的后续工作。失败、跳过、删除分别计数；提供最近执行、失败原因和审计跳转。
5. 涉及事务按同一顺序访问策略、组合、报告和对象行；策略与开关的停用写入须和执行事务的版本检查互斥。停用返回成功后不能再提交新删除。已提交的业务删除无法由关开关恢复。GC 宽限期只服务物理回收，不提供用户恢复承诺。

## 5. 开发切分与上线验收

| 交付单元 | 主要落点 | 可验证的完成条件 |
| --- | --- | --- |
| M1 个人记忆 | internal/store、internal/service、internal/authz、server、Chat 管理卡 | 本人新会话可取回经验；他人、同名 namespace 的另一集群、缺任一附加范围权限、仅有报告权限均无法读取。重复提交只有一行；并发编辑有冲突提示。 |
| M2 问诊召回 | Agent 模型请求装配、会话压缩边界、Web 引用展示 | 502 示例中能引用旧线索并根据本次时间线推翻旧归因。模拟模型捕获实际请求验证撤权、过期、遗忘及模型切换；用哨兵值检查 SSE、历史、摘要、审计和数据库，Secret 专用响应与 ModelOnly 不能流入记忆。 |
| R1 策略与预览 | internal/settings、store、报告服务、管理页 | 存量 enabled=true 升级后零自动删除；D/N 边界、相同时间排序、归属缺失、活动依赖、管理员与普通配置角色均有用例。预览零业务写入。 |
| R2 调度与事务 | 平台服务启动/停止、报告事务、审计中心 | 两实例抢占、租约过期接管、提交后进程退出、手动删除竞争、策略停用、GC 已清账、多个报告共用 blob 均可复现。核对业务行、引用数、审计和 run 明细，重试不能重复扣减。 |

迁移采用新增字段与索引、默认关闭、先发布可读取新结构的代码，再按能力激活。Memory 和 Retention 可分别回退到关闭状态。开发前确认现有报告生产路径能提供哪些活动依赖信号；无法确认的类别保持排除并在预览列出原因。MySQL 真库须验证事务隔离、索引和双实例接管，不能只用 mock 证明并发语义。上线前还需通过真实浏览器的保存、撤权、遗忘、预览与停用流程。四期原 P5.1–P5.8 和 7 人日保留为历史基线，专项评审通过后按 M1/M2/R1/R2 重排，分别记录验收结果。

# 问诊 Chat 界面与任务进度优化方案

- 版本：v1.0
- 日期：2026-11-19
- 状态：设计稿，待安排实施；本文不代表功能已交付。
- 基线：当前仓库 `68117bb`；承接 [方案 25：Chat 流式输出与前端展示统一](25-方案-Chat流式输出与前端展示统一.md)，不替代其事件、授权或恢复规则。
- 参考：[DSH Desktop](https://github.com/anywhere-labs/dsh-desktop) 和用户提供的输入区截图；借鉴卡片内工具栏和底部轻状态，不移植其运行时或权限模式。

## 1. 目标与范围

1. 输入区只突出提问、模型和发送／停止，目标集群继续由会话绑定并在页头显示。
2. 用户不翻原始工具日志也能看懂：Agent 本轮做了什么、正在做什么、是否需要我操作、哪些结果还不能下结论。
3. 上下文圆环显示 Agent 实际采用的**请求预算**，不显示累计 Token 消耗、缓存命中率，也不把估算说成供应商实测。
4. 保留现有会话、时间线、过程组、工具和审批卡、Go Runtime 及 SSE／快照链路。不做固定四步、计划调度器、自动审批、附件上传、跨集群分叉或 Agent 自动恢复执行。

## 2. 信息布局

```text
页头：目标集群：生产 A                         连接状态（断线单独提示）
时间线
  用户问题                                     复制 · 14:32
  [本轮任务  2 项已处理 · 1 项待确认]           展开查看
    ✓ 查询 default/api 的 Pod                发现 2 个副本重启
    ! 查询该 Pod 的事件                       无权限 · 证据缺口
    ◷ 重启 Deployment default/api            等待人工确认  → 查看审批
  [现有审批卡 / 最终回复 / 重要风险提示]
  最终回复                                     复制 · 从这里开启新会话 · 14:33
输入卡片
  输入你的运维问题…
  [人工审批 ⌄]                               [当前模型 ⌄]  [发送／停止]
底栏：等待你确认重启 · 查看本轮任务              ◔ 上下文预算 · 约 66%
```

示例合并展示各区的位置，不表示等待审批时已有最终回复。运行态底栏链接定位当前回合的任务列表；空闲态显示「上一轮任务」，历史回合从各自的时间线入口查看。卡片右侧仅在多个可选模型时显示下拉。去掉脑图标、`Secret: create_only` 和回合标题的 Token 消耗；附件只预留布局，不放失效按钮。「人工审批」是生效策略说明，不是权限开关；首版不显示「帮我审批」。

## 3. 本轮任务：真实动作清单，不是预估进度

### 3.1 展示规则

- **先看动作，再看详情。** 行标题优先是「动词 + 目标」，如「查询 Pod 事件」「读取 Deployment 状态」；目标取现有脱敏结构化字段，取不到则仅显示动作。结果行用简短的事实摘要；原始结果、命令和审批操作仍在现有卡片，任务行可定位并展开该卡片。
- **运行态默认展开简表，结束后折叠。** 用户手动展开／折叠后优先尊重选择；列表较长时默认聚焦活跃项和重要异常，可展开全部。待审批卡、未核实的变更结果和影响结论的证据缺口不能随任务表折叠而消失。普通问答没有工具和交互时，不展示空任务列表，只显示有依据的「准备请求／正在生成回复」。
- **只数已出现的事项。** 摘要如「3 项已处理 · 1 项待确认」；「已处理」是已进入终态，不等于成功，旁边另列失败／受限／未知。未知结果也可计入已处理，但必须单独警示。没有已知总任务数时不显示百分比、不预填虚假的待办，也不把模型推理、观察、流式分片和回复生成算作任务。
- **不把回合完成当作现场恢复。** 「已给出回复」「变更结果已确认」「故障已恢复」是不同事实。只有实际观察支持时才展示恢复；写结果未知显示「变更结果未知，先核实现场」，不得建议直接重试。

### 3.2 权威数据和映射

| 数据 | 规则 |
|---|---|
| `tool.updated`／快照工具项 | 按 `turn_id + tool_call_id` 更新同一项，按 `item_order` 保持首次出现顺序；同一调用的开始、更新和结果不重复计数。真正的新调用 ID 另计；只有后端明确标记重试关系时才显示「重试」。 |
| `interaction.updated`／快照交互项 | 有明确工具关联就把审批或追问状态挂到该行下，不叠加计数；未关联的独立追问／批量确认各算一项，不按时间猜关联。关联信息后来补齐时去重合并。 |
| 工具状态与结果 | 初始／通用运行态用「处理中」；只有可靠的操作类型及执行事实才写「正在查询」或「正在执行变更」。成功、失败、拒绝未执行、结果未知分别展示；有明确权限错误时用「查询受限」。 |
| 审批／等待 | 区分「等待补充信息」「等待确认变更」「等待同意读取 Secret」「等待提供创建所需的值」。批准不等于已执行；拒绝不展示「执行中」。实际操作仍通过原审批／问答卡，原授权边界不变。 |
| Turn 和连接状态 | Turn 决定本轮是否结束、失败或取消；不能批量推断子项结果。终态时仍未收到终态的工具项标「未取得结果」，特别是变更不能推断未发生。SSE 断开显示「正在同步，进度可能滞后」，不把任务标失败。 |

首版由同一份规范时间线数据派生任务视图，不读取内部 `Step` 或审计列表，不另建表和事件流。纯前端阶段数据不足时显示中性文案；需要区分只读／变更或准确执行阶段时，在原工具事件／快照补充可选的公开操作类型、目标和执行事实，后端负责来源，不能按工具名或命令文本猜。历史和实时共用归并逻辑；快照刷新、游标补齐和会话切换不得重复或串轮。

## 4. 上下文圆环：准确的是口径，不是伪精确的 Token

当前实现通过已有 `turn.status` 及规范快照传递预算样本。快照从保留期内的最新回合状态事件恢复该值；旧事件清理后，历史样本显示「—」，不重新估算。

### 4.1 配置与计算

当前单模型的分母来自配置中心的 `agent_context_window`（配置键 `agent.context_window`）；输出预留取本次请求生效的输出上限，当前问诊通常来自 `llm.max_tokens`。不是单条用户输入上限 `llm.max_input_tokens`，也不是累计上限 `llm.max_total_tokens`。

| 量 | 含义 |
|---|---|
| 生效窗口 | 当前模型可用的输入＋输出总窗口。单模型沿用现有配置；多模型阶段给每个模型单独配置，旧配置作为旧默认模型的兼容来源，不把旧全局值强套给所有新模型。若明确存在更小的部署限制，采用经确认的较小值。 |
| 可用输入预算 | 生效窗口 − 本次请求输出预留，两者必须在保存或装配时校验，输入预算须大于零。 |
| 估算已用 | 当前主 Agent 请求完成裁剪／压缩，实际发送输入组装完毕后，用与预算守卫相同口径计算。覆盖实际发送的系统提示、历史、当前问题、证据与工具定义；不含未发送草稿、另一次摘要请求或其他历史请求的消耗。 |
| 占用／剩余 | 占用 = 估算已用 ÷ 可用输入预算；剩余 = (可用输入预算 − 估算已用) ÷ 可用输入预算。按未舍入原值判定阈值，仅显示时舍入。超预算另提示超出量，圆环可画满但不能吞掉超限状态。 |

**私有模型示例**：如果部署侧确认「128K」是 **131,072 Token** 的总窗口，就填 `131072`；如果实际限制是 **128,000**，就填 `128000`，模型宣传值不能代替部署配置。以 `131072`、输出预留 `4096` 为例，可用输入预算是 **126,976**；本次估算输入 **83,804**，展示「上下文预算 · 约 66%」，Tooltip 显示「总窗口 131,072 / 输出预留 4,096 / 可用输入 126,976 / 估算已用 83,804 / 约剩余 34%」。

现有守卫用序列化 UTF-8 字节及附加开销做保守估算，不是模型 tokenizer，中文、工具 schema 和长日志可能与供应商的 prompt token 计数有差距。**首版验收“同一请求、同一配置、同一估算器，守卫与圆环一致”**，不承诺等于供应商实测。若业务要求真实 Token 占用，应接入该私有模型部署实际使用的 tokenizer／计数端点（含聊天模板和工具定义），并与供应商样本比对后再将其纳入守卫；响应里的单次 `prompt_tokens` 可用于校验，但不回填成下一次请求的占用。

### 4.2 采集与显示

- 在 Runtime 层生成结构化预算值，初步建议给现有 Turn 更新与快照追加可选 `context_budget`：模型标识、请求标识／顺序、窗口、输出预留、输入估算、估算方法、采样时间与状态。按现有事件／快照持久化规则复原最近一次，前端只按服务端数字展示；缺失则为「—」，不以零补齐。上线前检查严格协议校验和新旧端兼容，不能兼容时按方案 25 的协议升级机制处理。
- 预算采样点必须与守卫共享。若模型请求在守卫后还有载荷追加（包括当前轮获准的 ModelOnly 内容），要在最终发送边界补做同口径校验，避免凭早期数值作出保证；只输出预算统计，不输出输入正文或能够单独推导敏感值的分项。敏感请求若无法安全公开统计，则该次只显示「预算详情不可用」，不沿用旧数值冒充当前请求。
- 仅随有效请求变化更新，不随流式分片或打字抖动。压缩成功可下降；接近现有压缩触发线是提醒，不是失败。压缩后仍超限时明确提示并引导缩小问题范围或开启新会话；不要把接近满额当作已经超限。
- 空闲时标「上次请求」，沿用该次模型和窗口；若已选择不同模型、配置已知变化或会话切换到暂无样本的目标，先显示「—」，不把旧分子套新分母。悬浮、键盘聚焦和触屏点击都能查看说明。

## 5. 组件与其他交互

| 组件／区域 | 改动 |
|---|---|
| `ChatView`、`useChatStream` | 保留会话、运行状态与恢复职责，派生底栏选中的回合。停止用既有取消接口；点击后显示「正在停止…」，终态后恢复输入，失败可重试取消／重新同步；不会撤销已发生的操作。 |
| `ComposerBox`、`ComposerToolbar` | 保留发送快捷键、中文输入法和 `@Skill`。工具栏呈现策略说明、模型和发送／停止，不改变审批配置。 |
| `TurnBlock`、`AgentTaskList`、`AgentStatusBar` | 任务列表是规范时间线的简要视图，原有过程与卡片保留为详情；底栏只显示当前动作、任务入口、预算圆环。不新增一份全局运行状态。 |
| `MessageActions`、`MessageTimeline` | 仅提问和最终回复提供复制与时间；复制已脱敏正文。时间取对应消息事件或明确标注为回合时间，不用当前时间补历史。保留流式贴底和手动上滑暂停，只有点击「回到底部」时平滑滚动；确有新内容才提示。 |
| `MarkdownView`、`StructuredTable` | 沿用清洗、复制和长代码折叠；新增斑马纹、宽表独立横向滚动、明确的数字列对齐。高亮按需加载且不放宽清洗；资源进度条只绑定可信结构化数值、单位和阈值，缺值不画，保留文字读数。 |

## 6. 后续独立交付

### 6.1 模型目录与探测

配置中心提供「API 格式」下拉，当前唯一受支持的格式为 OpenAI 兼容 Chat Completions；原生 Anthropic Messages 和 OpenAI Responses 尚未适配。已保存的连接配置用于候选发现和基础推理探测。候选可填写总窗口后加入问诊目录；目录保存后，Chat 可在空闲时选择下一轮模型。体检仍使用配置的默认模型。

- 首版以现有提供方配置为基础新增启用模型目录；「自动获取」在配置中心由后端使用配置好的提供方请求，结果仅进入候选列表，人工确认后启用，支持手填。
- 分开显示「列表已获取」与「模型已验证」。模型探测使用短超时、限频、无业务数据的最小请求；能访问列表不代表能生成或完成工具问诊。校验必要的能力或明确标记尚未验证，不从模型名猜上下文容量。
- Chat 只读可选模型公开元数据；配置、凭据和探测留在后端并按权限开放。请求按允许的 `modelId` 固定本轮模型，纳入幂等指纹，记录实际模型；运行中不切换，失效要求重新选择，不静默降级，不影响体检默认模型。

### 6.2 从历史开启新会话

当前已支持从本人已完成的最终回复创建分支；来源仍可访问时可返回来源会话。创建使用持久化切点和幂等请求标识，脱敏问答与新时间线在同一事务保存。

- 首版只在**已完成回合的最终回复**上提供入口；新会话继承截至该回合的脱敏问答上下文，记录来源会话／回合。不先实现任意消息切点、会话树或跨集群分叉。
- 服务端按稳定 ID 查持久化历史，不接受前端上传的上下文，不从后续会话摘要倒推截点。首版继承脱敏用户问题与最终回复；不直接继承工具原文、审批、授权、任务状态、Secret 明文或可揭示明文的引用。历史事实要标注为历史，当前操作仍需实时核实。
- 创建时复核来源访问和目标授权，限制同一集群且源会话没有未完成操作；首次执行照常复核。新会话有自己的运行与审计，不复制审批、不重跑工具、不自动发送；失败不改源会话。来源跳转按当前权限独立校验。

## 7. 分步实施与验收

| 阶段 | 交付 | 验收门槛 |
|---|---|---|
| 1：视觉与交互 | 输入卡片、策略说明、消息复制／时间、滚动／停止、表格基础样式 | 不改权限和运行协议；单模型不做假下拉；中文输入、窄屏、深浅色、上滑阅读、刷新后停止入口和取消失败均可用。 |
| 2A：本轮任务 | 先基于已有事件做列表、定位和底栏入口；若语义不足，补公开执行事实 | 普通答复无空列表；同一工具多次事件只计一项；审批拒绝不显示已执行；弱网重连不重复；查询受限、写结果未知能直接看见，不与整轮状态混淆。 |
| 2B：上下文预算 | 单模型就可接入，不等待模型目录；复用预算守卫与 SSE／快照 | 用 128K 模型配置核对公式与守卫，覆盖中文、长日志、工具 schema、压缩、超限、缺数据、敏感通道和重连；不显示跨模型的旧占用。 |
| 3：多模型 | 配置中心发现和测试、Chat 下一轮选型 | 列表可达不冒充推理可用；实际模型与显示一致；模型窗口独立；未获授权的模型不可选，凭据不回传；体检不受影响。 |
| 4：分叉 MVP | 从一个已完成回复新建会话、来源回跳 | 无后续消息混入；无权限继承、无明文、无工具重放；授权撤销、重复提交与并发分叉有明确行为，源会话不变。 |

实施优先级为 **1 → 2A／2B → 3 → 4**。每阶段独立验收；其中任务列表和圆环是本方案的体验重点，模型目录和分叉不是首版改版的前置条件。

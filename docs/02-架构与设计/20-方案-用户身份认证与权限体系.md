- 版本：v2.0
- 日期：2026-11-07

- 适用范围：单实例、单工作空间部署的 Kubernetes 企业运维 Agent，覆盖 Web、平台 API、Agent、体检、报告和审批。

## 1. 产品定位与范围

AegisOps 提供 Kubernetes 体检、证据化诊断和受控运维。身份体系用于接入企业用户、隔离业务数据并约束 Agent 执行；不建设通用 IAM。

本次交付：本地账号、一个标准 OIDC Provider、统一内部用户、admin/user 两种平台角色、按集群与 namespace 的资源授权、独立集群资源授权、会话撤销、数据访问控制、执行复核和审计。

本次不交付：自助注册、邮箱找回、组织/部门/租户、用户组管理、自定义角色/策略语言、原生 CAS/SAML/任意 OAuth2 登录、多 Provider、SCIM、跨实例会话与高可用。外部服务身份、API Token 认证、Remote MCP 接入另行设计，不混入人类登录。

平台默认单副本。认证会话、OIDC 登录事务和运行任务允许保存在进程内；重启需要重新登录。数据库中的对话、报告和审计按保留策略恢复。用户版本号机制不代表支持多副本认证。

## 2. 已确定的架构决策

| 编号 | 决策 |
|---|---|
| D01 | 认证来源仅 local/OIDC，均映射到唯一内部 UserID；OIDC 外部主键为 issuer + sub |
| D02 | 平台角色仅 admin/user；删除 operator，不做旧 operator 用户转换 |
| D03 | admin 对已登记集群自动拥有平台资源权限，无需给自己创建 Grant；实际执行仍受所选集群凭据的 Kubernetes RBAC 和人工审批约束 |
| D04 | 普通用户的资源授权以 AuthzGrant 为唯一权威；admin 由平台角色取得已登记集群权限，后端统一判定，前端有效权限视图仅供展示 |
| D05 | 每条授权关联一个明确 ClusterID、一个资源范围和动作集合；禁止空 ClusterID、跨集群通配和拆散范围后的全局动作合并 |
| D06 | namespace 是默认业务边界；所有 namespace 与集群级资源是两个独立范围 |
| D07 | 资源访问、平台功能、数据归属和审批分别判定；审批不能授予缺失的资源权限 |
| D08 | 每次工具调用及审批恢复后重新核权；授权成功不是整轮 Agent 的永久通行证 |
| D09 | Web 使用服务端不透明会话和 HttpOnly Cookie；不在浏览器 localStorage 保存认证凭据 |
| D10 | 复用成熟 OIDC 协议库；借鉴 Argo CD 身份设计、Rancher 授权分层，不整体复制其系统 |
| D11 | 本版平台通过托管 Kubernetes 凭据执行；不要求业务集群信任企业 OIDC，不自动创建用户 RoleBinding 或启用 impersonation |
| D12 | 未明确放行即拒绝；资源范围无法可靠解析的调用不得靠模型解释或真人审批补齐权限证明 |

admin 的资源权限来自平台角色，仍须选择已登记集群；高风险操作的真人审批与审计继续生效。因此本版不宣称具备管理员与授权审批人的职责分离。

## 4. 用户身份与平台角色

### 4.1 统一内部用户

UserID 是不可变、不可复用的内部主键。用户名、显示名、email 均不作为授权主体键；Grant 只接受内部 UserID，不再兼容 username 匹配。

本地用户由 admin 创建；不提供公开注册。OIDC 用户通过登录准入后首次创建为 active user，无资源 Grant。OIDC-only 用户无本地密码；本地登录必须拒绝空密码哈希。

外部身份只按经验证的 issuer + sub 关联；email 相同不自动合并。第一版支持一个本地用户绑定一个 OIDC 身份：需要本地密码重新验证和完整 OIDC 认证，绑定事务必须标注用途，不能误走首次创建流程。解绑同样需要重新认证，且不能移除最后一种可用登录方式。禁止 admin 仅填写他人 sub 即完成绑定。

### 4.2 平台功能矩阵

| 能力 | user | admin |
|---|---|---|
| 登录、登出、查看本人身份/有效范围、本地用户改密 | 允许 | 允许 |
| 创建与使用本人 Agent 会话 | 允许，Kubernetes 调用另验资源 Grant | 同左 |
| 发起体检、读取报告 | 允许，另验范围与数据访问规则 | 同左；治理读取见第 9 节 |
| 使用已启用、适用的 Skill/Tool | 允许；执行不超出本人资源范围 | 同左 |
| 查看其他用户会话/任务/报告、取消运行、按策略清理业务数据 | 禁止 | 允许，逐次审计 |
| 向他人会话发送消息、接续执行、代替他人审批 | 禁止 | 禁止 |
| 用户、OIDC、Grant、集群凭据、平台配置、Skill 管理 | 禁止 | 允许，逐次审计 |
| 全平台审计查询 | 禁止；本人会话可看脱敏操作记录 | 允许 |
| 删除或改写审计记录 | 禁止 | 禁止 |

`scan.execute` 归入两角色共有的基础功能权限，资源范围与并发限制仍强制执行。角色不形成 viewer/operator/owner 等额外身份。后端返回有效能力供前端显示；管理菜单隐藏不承担安全职责。

### 4.3 用户生命周期

状态为 active/disabled/deleted（deleted 为保留身份引用的逻辑删除）。停用禁止新登录并撤销已有认证会话；删除先停用、撤销 Grant 和未完成审批，保留审计及业务对象的不可变作者标识。重新创建同名账号获得全新 UserID。

至少保留一个 active、可通过本地密码登录的 admin。并发的停用、删除、降级、解绑均须在事务内检查这一不变量，保护依据是用户身份与剩余能力，不硬编码用户名 admin。首启创建本地应急 admin；已有库缺少有效管理员时明确报错并走受控恢复，不覆盖现有账号或静默重设密码。

## 5. 认证、登录与会话

### 5.1 本地认证

复用当前 Argon2id 参数与安全哈希格式，密码最少 8 字符，限制请求体和密码最大长度。错误用户名/密码/停用账号统一失败。按账号标识与可信来源 IP 分别限流，使用有容量上限的内存记录；默认账号连续 5 次失败冷却 5 分钟，IP 每分钟最多 30 次登录尝试，超限返回 429。代理 IP 仅信任静态配置的反向代理。

改密验证旧密码，重置密码仅 admin 可操作；两者成功后均原子递增 session_version 并注销全部旧会话，用户重新登录。密码及哈希不进入响应、日志、审计或模型。

### 5.2 OIDC

只支持标准 Authorization Code + PKCE S256；不支持 implicit flow，不将任意 OAuth2 UserInfo 接口视为通用登录。企业 MFA、组织管理由 IdP 承担。CAS/SAML 环境优先由企业身份代理提供 OIDC，本版不内置 Dex 或 Keycloak。

默认 scopes 为 openid/profile/email；groups 仅在配置准入规则时按需请求。应用登录资格优先由企业 IdP 的应用分配控制；也支持一个明确配置的 allowed_groups 白名单，按经验证的 group claim 精确匹配，缺失时拒绝。组在此仅用于登录准入，不创建平台组、不赋角色或资源 Grant。不得提供含糊的“只要同邮箱域就合并/授权”规则。

流程：发起登录 → 服务端生成一次性事务 → 跳转 IdP → 回调校验 → Code 交换 → 验证 ID Token → 检查准入与内部状态 → 按 issuer/sub 查找或首次创建 user → 签发 AegisOps 会话。必须检查签名、issuer、audience/必要 azp、exp/iat 等时间约束与 nonce，使用安全随机数且随机失败时拒绝，不降级为时间戳令牌。

登录事务默认 TTL 5 分钟，内存存储，容量受限；保存 state、nonce、verifier、用途、配置版本和校验后的站内返回路径。短期 Secure/HttpOnly/SameSite=Lax Cookie 绑定浏览器。state 匹配后原子消费事务，失败、过期、重放、换浏览器均拒绝。state、nonce、challenge 可作为协议参数出现在授权请求；verifier、完整事务、Token、密码和 Client Secret 不进入 URL/日志。

OIDC Token 留在服务端，完成本次校验后释放，本版不保留 Refresh Token、不请求 offline_access、不做静默续期。UserInfo 如被使用，sub 必须与 ID Token 一致。回调完成后跳转干净的站内地址，响应使用 no-store，并避免 Referer 泄漏授权码。

### 5.3 Web 认证会话

认证会话与 Agent 对话是不同对象。认证会话是进程内随机不透明令牌，记录 UserID、session_version、认证来源、创建/到期/最后活动时间及 OIDC issuer；服务端保存令牌哈希用于查找。生产 Cookie 使用 Secure、HttpOnly、SameSite=Lax、Path=/，不配置 Domain；HTTPS 生产环境使用 __Host- 前缀。开发环境的 HTTP 例外必须明确配置且仅允许回环地址。

默认绝对有效期 8 小时、空闲有效期 30 分钟；OIDC 会话到期时间不晚于本次 ID Token 的 exp。到期必须重新认证，不能因访问或流式心跳突破绝对期限。SSE 心跳不刷新用户活动。

状态变更请求须通过可信 Origin 校验和与会话绑定的 CSRF Token 校验；登录也须防跨站提交。OIDC callback 使用一次性 state/nonce/浏览器绑定。GET 不得修改业务状态，前后端采用同源 /api/v1；SSE、下载和平台 API 使用同一认证会话。Cookie、OIDC Token 均不得进入 localStorage、sessionStorage、SSE query string 或页面脚本。

每次请求检查权威 UserStore 的 active 状态与 session_version；改密、重置、停用、删除、平台角色变化或身份解绑时递增版本并清除本实例会话。用户/版本读取失败时拒绝，不使用旧权限缓存兜底。已建立的 SSE 至少每 30 秒复核会话，失效关闭连接；后续工具调用按第 8 节另外核权。

### 5.4 登出与企业停用

退出 AegisOps 使用受 CSRF 保护的 POST，删除服务端会话并清理 Cookie。第一版仅承诺本产品登出，不承诺退出全部企业应用或结束 IdP 浏览器登录；UI 应明确“企业登录状态可能仍有效”。

企业停用不自动撤销已经签发的 AegisOps 会话。内部停用立即阻断新请求与后续工具调用；仅发生上游停用时，旧会话可用至本地到期。下一次真实企业认证的停用传播取决于 IdP 配置。该窗口必须写入部署验收，不能宣称离职实时同步。Back-channel logout/SCIM 为后续能力。

## 6. 资源授权模型

### 6.1 Grant 最小结构

每条 Grant 包含：id、user_id、cluster_id、scope_type、namespaces、resource_profile、actions、expires_at、created_by、created_at、updated_at。只允许 admin 创建/修改/撤销；主体与 ClusterID 创建后不可改，换主体或集群须新建。目标用户和集群必须存在且可用。

| 字段 | 第一版规则 |
|---|---|
| cluster_id | 必填，指向登记集群的内部 ID；平台自身集群也必须登记，拒绝空值/通配 |
| scope_type | namespace 或 cluster |
| namespaces | namespace 范围为明确名称列表或单独的 ["*"]；cluster 范围为空。禁止前缀/glob/正则 |
| resource_profile | builtin_namespaced 或 builtin_cluster；实际 GVR/subresource 清单在受版本管理的工具访问契约中列出，用户不编辑任意表达式 |
| actions | 从固定动作中选择，不接受旧的 * 权限字符串 |
| expires_at | UTC，可为空表示永久；到期即失效。编辑显式 null 表示取消到期时间，不把清空解释为保持原值 |

### 6.2 固定动作与授权交互

| 动作 | 含义与限制 |
|---|---|
| read | 读取配置的资源视图、状态、Events、获准的 ConfigMap 内容与 Secret 键级元数据；不含日志、Secret 内容或执行命令 |
| logs | 读取范围内 Pod 当前/历史日志，必须同时具有同范围 read；展示与模型请求前脱敏 |
| operate | 在固定资源清单内申请 create/update/patch/apply/replace/scale/rollout 等非删除变更，必须同时有同范围 read；审批另验 |
| destroy | 申请删除固定资源清单内对象，所有 delete/deletecollection 都归此动作；必须同时具有同范围 read 与 operate；审批另验 |
| exec | 对范围内明确 Pod 执行非交互命令，必须同时有同范围 read 与 operate，逐次真人审批 |
| secret.read | 仅对范围内明确 Secret/key 发起 get_secret_value，必须有同范围 read、启用 read_on_demand，逐 key 真人审批 |
| shell | 仅 cluster 范围可配置的高级执行能力，另须覆盖全部 namespace 和集群资源的 read/logs/operate/destroy；逐次真人审批，仍受硬拒绝规则约束 |

授权页提供“只读诊断”（read+logs）、“普通变更”（read+logs+operate）、“允许删除”（再加 destroy）三个固定组合；它们是快捷选项，不是新增平台角色。exec/secret.read 为明确标记风险的额外开关。shell 仅在高级集群授权中出现，缺少全部前置权限不能保存。

builtin_namespaced 首版覆盖工具已支持的工作负载、Pod、Service/Endpoints/EndpointSlice、Ingress、PVC、ConfigMap、HPA/PDB、Events 与 Secret 元数据。builtin_cluster 的 read 覆盖 Node、PV、StorageClass、Namespace 的诊断视图；集群 operate/destroy 首版只开放现有执行器明确支持的 Node/PV/Namespace 操作。具体 API group/resource/verb/subresource 必须有机器可检验的清单，新增工具或资源必须同步更新。

普通资源组合不授权 Secret 内容/Secret 变更、ServiceAccount、RBAC 绑定、CRD、Webhook 配置、任意自定义资源或凭据管理；已有专用 Secret 创建通道需纳入单独安全能力评审，本版普通用户不沿用默认放行。未覆盖资源可以展示待执行建议，但不得因为 kubectl 能表达就绕过授权。此限制不取消 kubectl 作为已支持操作的 fallback。

Secret 元数据始终通过现有 scanner/reader → kubernetes 只读门面或专用结构化视图获取，仅暴露名称、类型、键名和 immutable；不能先把含 data/stringData 的对象交给 Agent 再做展示隐藏。新增 GVR 支持由开发维护访问契约并补测试，无需新增角色或用户授权语言。

### 6.3 匹配规则

一次调用先规范化为若干目标元组 `(ClusterID, scope, namespace, GVR, subresource, action)`；来源是服务端可信集群上下文、工具访问契约及解析后的参数，不能由模型填写 required_permission。

对每个目标，在该具体范围内合并当前有效 Grant 的动作，再逐项检查必需动作。允许只读与变更来自同范围不同 Grant；禁止在合并后把 A namespace 的 destroy 扩散到 B namespace。批量、全 namespace 查询、manifest 多文档和复合操作必须覆盖全部目标，任一无法判定或未授权则整体拒绝，禁止默默缩小执行范围。

`namespaces=["*"]` 包含当前及未来所有 namespace，授权 UI 必须提示；它不包含 Node/PV 等集群级资源。cluster 范围不隐含 namespace 访问。需要创建/删除某个 namespace 对象时另验 cluster 范围的对应动作，不能由该 namespace 内的 operate 推导。

第一版不接受 group Grant，不开放组管理。旧 group 数据不得参与有效权限计算。授权主体只认 UserID；到期、撤销和用户停用实时用于下一次判定。可访问集群列表只提供显示名/连接状态/有效范围，不泄漏地址、kubeconfig 或凭据。

### 6.4 诊断完整性

跨 namespace、节点或存储依赖不自动扩权。缺少读取权限时，标记“超出授权范围，未采集/未验证”，保留已确认事实，不推断资源健康。工具、体检报告和最终回答都应体现证据缺口。

namespace 体检只使用获准数据；预设要求但无权限的可选采集项明确跳过，不能扩权或假装完成。全集群完整体检需要全部 namespace 的 read/logs 与集群 read。单独 cluster read 不等于可以读取其他 namespace 日志。按故障关联提供受限 Node/PV 字段投影留待后续，不在本版隐式实现。

## 7. 集群上下文与执行凭据

集群接入由 admin 管理。每个执行目标必须有稳定内部 ClusterID，并关联具体连接配置/凭据版本。客户端可以请求选择集群；admin 可选择已登记集群，user 只可选择有效 Grant 覆盖的集群。不能提交任意 API Server、kubeconfig 路径、kubectl context 或 impersonation 参数覆盖目标。

一条 Agent 对话绑定一个 ClusterID，创建后不可改。页面切换集群时打开该集群的新会话或切回其已有会话，不把旧集群聊天、证据和审批带到新集群。无授权用户可以进入空工作台，但首次 Kubernetes 调用前必须明确选择有效目标。

工具、体检、报告归档和审批继承同一服务端目标。执行器的 Kubernetes Client 与 kubectl KUBECONFIG 必须从该 ClusterID 解析；模型参数不选择实际连接。凭据文件仅在 executor 内受控使用，清理生命周期明确。连接变化使未完成审批失效；复用 Client 的缓存键包含集群/凭据版本，不能按一个全局默认 Client 执行。

本版采用平台托管执行身份，其实际能力由 Kubernetes RBAC 与准入控制约束。平台内部用户授权由 AuthzGrant 强制执行；SelfSubjectAccessReview 只探测托管凭据权限，不证明最终用户已有授权。API Server 的实际拒绝是最终结果，SAR 错误不得解释为允许；可说明预检查不可用并由实际请求验证已获平台授权的操作。

read 与变更凭据可由部署侧分别配置，平台应使用满足功能的最小权限；不承诺平台 Grant 会自动生成集群 RBAC。用户 OIDC Token 不转发给 Kubernetes。面向更强隔离的按用户 impersonation/派生 RBAC 为独立后续方案，不能混用旧文档的假定。

## 8. Agent 授权、审批与安全执行

### 8.1 统一检查链

```text
认证会话有效 / CLI 明确执行上下文
  → 用户 active、session_version、平台功能权限
  → 对话 owner 与可信 ClusterID
  → 规范化完整目标集合、读取当前有效 Grant
  → 逐目标校验资源范围、动作、专项能力
  → Code Guard 硬拒绝规则、输入与 manifest 检查
  → Kubernetes 执行身份能力预检查（可用时）
  → 本次操作是否需要真人审批
  → 审批恢复后再次核权、校验目标/参数/凭据版本
  → internal/executor 执行
  → 验证结果、脱敏、审计与持久化
```

后端应用服务统一提供 Authorize/EffectiveAccess 能力，供 Chat、Scan、Report 和下载复用。AccessScope 可以保留为前端/模型的能力摘要，但不能继续作为整轮执行的唯一授权快照；禁止用 IsAdmin 或 ClusterScoped 布尔值提前跳过动作检查。

运行开始时由服务端构建可信 AuthContext，至少包含 source、UserID、authSessionID/session_version、conversationId、ClusterID 与凭据版本；HTTP 请求结束后，后台运行仍以该上下文核验原认证会话到期/撤销状态。不能只保留 UserID 而使已登出或到期的运行继续获得新调用权限。业务服务不依赖 CLI；Kubernetes 写调用及 kubectl/shell 执行仍仅位于 internal/executor，读路径继续使用现有只读门面。

工具必须声明访问契约，服务端解析真实 GVR、namespace、动作及子资源。未注册契约的工具默认拒绝；kubectl 的 get/logs/exec、manifest 多对象、集群对象、重定向和管道均有测试。新增功能不能靠角色判断散落放行。

### 8.2 审批语义

只读且无 shell 构造的已授权调用自动执行；普通写操作进入现有审批策略。exec、shell、get_secret_value 恒逐次真人审批，不允许“本会话全部允许”、白名单或 --skip-permissions 绕过。交互/blocking 命令、--raw 和直接 kubectl Secret 访问继续硬拒绝。

审批记录包含 ApprovalID、申请人 UserID、认证会话版本、对话/运行 ID、ClusterID、凭据版本、规范化目标、参数摘要/哈希、所需动作、风险、创建/到期时间、审批人及决策来源。默认有效期 5 分钟且不超过调用/运行期限；单次原子消费，重放拒绝。

第一版采用申请人对本人操作的确认模式，不建设第二审批人流程。只有发起该运行的用户可以确认；admin 可查看/取消他人的审批与运行，不得代批。UI 将其称为“操作确认”，不能宣传为双人复核。未来专门审批人设计与平台 admin 身份分开。

确认前必须展示实际集群、namespace、资源、具体命令/变更、风险和预计影响。审批后目标、参数、权限或凭据版本变化时拒绝旧审批；资源版本变化是否需重新确认按操作风险规则判定，高危操作必须重新确认。会话级普通写允许记录亦绑定集群与目标，不覆盖专项操作。

### 8.3 运行中撤权

每次工具调用前从权威数据重验用户和 Grant，审批等待结束后再次重验。停用、删除、撤销 Grant、到期或角色失效时，撤销适用的待执行审批，拒绝后续调用并记录原因。

长体检在采集批次/阶段边界及写入可访问结果前复核权限；撤权时尽力取消，不能继续投递撤权后新获得的数据。运行与 SSE 设有取消/失效通道。已经送达 API Server 的请求可能完成，不能承诺回滚；结果按当前数据访问规则处理，不继续发起新操作。记录请求时、复核时、执行时状态，不能只记最初登录身份。

### 8.4 专项操作与 CLI 边界

Secret 默认不进入 LLM；read_on_demand 下 secret.read 仅允许 get_secret_value 对明确 namespace/name/key 逐次真人审批。明文只进入当前一轮模型请求；不进入 evidence、SSE/UI、对话文件、数据库、审计、最终回答或后续轮次。非模型出口精确值脱敏，仅保留位置、长度和 SHA-256 指纹。外部模型提供方可见该值的边界须在部署文档说明。

非交互 exec 必须在 -- 后有显式命令，不得包含 -i/-t/--stdin/--tty；exec 和 shell 都不能成为读取 Secret 内容或绕过授权的替代通道。已知 Secret 文件/令牌提取、未知脚本或无法核验的复合目标按硬拒绝/无法判定处理。exec 是高信任能力，不能把任意容器内命令宣传成只读；部署方需限制 Pod 身份与挂载权限。

shell 仅在具有第 6 节全部前置能力的交互运行中开放。审批不能覆盖命令解析失败、不允许的程序、隐藏子命令或禁止资源访问；不能证明目标完整性的命令拒绝并提供结构化替代。namespace 受限用户始终不能用 shell 跨过资源门禁。--skip-permissions 仅跳过允许自动化的普通写确认，不绕过平台 Grant、Code Guard、Secret/exec/shell 限制或 Kubernetes RBAC。

平台 Web/API 不接受客户端提交 --skip-permissions 开关。独立 CLI 继续使用操作者本地 kubeconfig/ServiceAccount 与显式配置的执行上下文，不强制登录平台、不伪造平台 UserID；同一应用服务复用安全策略，审计标明 source=cli 与真实执行身份。CLI 如未来作为远程平台客户端，必须另走平台认证授权，不以本地模式绕过服务端。

## 9. 对话、体检、报告与证据访问

### 9.1 数据规则

| 对象 | 普通用户 | admin 治理访问 |
|---|---|---|
| 对话列表与历史/SSE | 本人对象，正文还需满足当前数据覆盖范围 | 可读取所有对话，进入治理视图并逐次审计 |
| 继续对话、操作确认 | 仅本人且当前资源授权有效 | 只能在本人对话执行；不得在他人对话运行 |
| 私有体检任务与报告 | 本人对象，且数据覆盖范围被当前权限包含 | 可查询、读取、取消和按保留策略清理，逐次审计 |
| 共享系统体检报告 | 无 owner 例外；当前权限覆盖完整报告范围才可读 | 可治理读取，逐次审计 |
| Evidence、Markdown、JSON、导出、下载 | 与原对象相同，禁止用格式或下载绕过 | 同上，敏感值仍全局脱敏 |
| Audit | 本人会话内的脱敏执行记录；无全平台查询入口 | 全平台查询，不能修改/删除记录 |

owner 表示数据归属，不覆盖当前资源授权。撤销资源权限后，普通用户可以看到本人历史记录的安全占位信息与“权限已变化”，不能继续读取越权正文、证据或下载缓存；已下载副本无法撤回，此限制须诚实说明。admin 的治理读取是显式数据权限，不授予实际 Kubernetes 执行能力。

管理员接手问题时新建本人会话并记录来源对象 ID，不继承原会话的审批或执行身份。删除对话/报告不删除其审计；保留任务采用系统身份与明确留存策略执行，不能提供 admin 手工清除审计 API。

### 9.2 数据覆盖清单

对话、体检任务、报告和归档产物记录服务端生成的 coverage：ClusterID、namespace 范围、集群资源类型、所需 read/logs 等数据能力、采集策略版本及 completeness。覆盖范围按实际采集和送入模型的数据确定，不能只按页面选择的 namespace 标注；无法精确判断时采用更宽的保守范围。

namespace 体检不得后台先扫描全集群再裁剪展示。全 namespace 清单、跨 namespace 关系、日志与原始证据都进入覆盖范围判断。对话 coverage 随消息/工具结果保守累加，同集群历史内容可能比当前一次问题更宽。

第一版不做完整报告的自动授权裁剪。权限不足直接拒绝完整正文/下载，给出可重新发起授权范围内体检的入口；不能仅隐藏页面某些卡片却开放原始 JSON。缺失 coverage 或 ClusterID 的历史内容仅允许 admin 治理读取，禁止猜测归属。

### 9.3 下载与缓存

下载统一经认证代理端点逐次核权，不向浏览器发可复用的对象存储公网链接或长期预签名 URL。异步导出句柄绑定请求用户和源对象，读取时重验；响应 no-store。业务文件可按保留策略存储，前端清理会话不等于服务端撤权，缓存不能脱离原对象授权。

## 10. 审计与可解释拒绝

关键事件：登录成功/失败/限流、登出、改密/重置、停用/删除/角色变化、身份绑定、OIDC 配置变化、Grant 生命周期、越权拒绝、工具执行、审批决策/失效、管理员跨用户读取与治理操作。

字段至少包含 eventType、actor UserID/来源、authSession 标识（非凭据）、requestId、conversationId、run/turn/tool/approvalId、ClusterID、目标元组、对象 owner、动作、决策/原因码、相关 Grant ID/策略版本、时间、可信来源 IP、结果。CLI 无内部用户时明确记录执行身份，不能用 system 冒充某用户。

记录最小必要元数据，不记录密码、Token、Client Secret、kubeconfig、Secret 值、对话正文和原始日志。管理员读取他人数据时先成功记录访问事件，再返回数据；审计不可用时拒绝敏感读取/写执行，不能静默成功。

本版使用现有 AuditStore 提供追加与查询，不提供业务删除/修改 API。生产部署配置独立的审计留存出口或由基础设施采集至受限日志存储，访问权限独立于普通平台 admin。未完成外部留存验证前，不宣称防篡改；同库记录或单独哈希链均不能等同于不可篡改。

内部保留稳定原因码，如 AUTH_REQUIRED、SESSION_REVOKED、CLUSTER_REQUIRED、SCOPE_DENIED、ACTION_DENIED、DATA_SCOPE_DENIED、APPROVAL_EXPIRED。用户提示解释缺少哪类能力及如何联系管理员，不暴露无权获知的资源详情；LLM 不改写授权结果。

## 11. 数据与服务接口设计

### 11.1 持久数据

| 实体 | 需要保留/增加的内容 |
|---|---|
| users | 不可变 ID、username/display_name、可空 password_hash、email、role_id、status、session_version、deleted_at、时间；display_name/status 已有，复用现字段 |
| user_identities | user_id、provider、issuer、subject、时间；UNIQUE(issuer,subject)，本版同一用户最多一条 OIDC 关联 |
| roles | 仅 admin/user，固定功能能力，清理 operator seed/约束/引用，不引入自定义角色 |
| authz_grants | 第 6 节明确范围与动作，主体/集群外键或等价一致性约束；按 user/cluster/expiry 查询 |
| 对话/ScanTask/Report/Object | owner、稳定 ClusterID、coverage、策略版本与来源关联；沿用现有业务 Store |
| Approval/Audit | 完整 actor/owner/目标/版本/参数摘要关联，不只存一条 yes/no |
| Settings | auth 组 OIDC 配置；敏感 Client Secret 用现有 Cipher 加密，只写不回显 |

认证 Session 与 OIDC 登录事务只在内存；数据库身份/授权数据为权威。auth_source 由是否具有本地密码与外部身份关联推导为 local/oidc/mixed，不再建立可漂移的第二个权威字段。email/显示名仅作展示，更新不改变授权。

### 11.2 逻辑接口契约

| 入口 | 契约 |
|---|---|
| 登录能力查询 | 未登录只返回本地/OIDC 是否启用及展示名，不返回 issuer、Secret 或完整配置 |
| 本地 login/logout/password、OIDC start/callback | 共用 Session 签发/撤销；callback 是经过一次性协议校验的公开入口 |
| /auth/me 与 /auth/access | 返回可信 UserID、平台能力和分集群有效范围，不返回跨 namespace 展平的 CanWrite/CanDestroy |
| users 与身份关联 | admin 管理用户；本人经重新认证完成绑定/解绑，服务端强制最后本地 admin 不变量 |
| grants | admin 管理，强类型输入、主体/集群校验、权限预览与保存审计，修改/撤销下一次判定生效 |
| 可访问集群 | user 只见被授权集群摘要；admin 的集群管理目录与执行选择器分开 |
| sessions/scans/reports/evidence/download | 每个入口进行对象与资源范围检查；任务/报告 ID 不构成权限凭据 |
| settings/auth | admin 可校验/测试/保存/启停；Secret 仅返回 hasValue，普通用户直调 403 |

除登录、OIDC 协议端点、健康检查及必要静态资源外，平台业务入口均需认证；公开入口也按其协议规则校验，不能笼统写成“所有端点都需先登录”。认证/权限失败状态码统一：401 未登录或会话失效，403 当前动作被禁止；普通用户访问他人私有对象使用 404 防枚举。权限计算失败拒绝并返回可诊断服务错误，不降级匿名或全权限。

现有 API Token CRUD 尚未形成平台认证闭环。本次不把它当成可用集成功能：停止新签发、隐藏 UI，遗留端点返回明确 FEATURE_NOT_ENABLED，旧凭据不自动转成登录会话；迁移时标记撤销。未来机器身份具有独立范围、到期、轮换与审计设计，禁止复用应急 admin 密码做集成。

## 12. 产品页面与关键流程

管理入口收敛为“用户与授权”，含用户、资源授权、企业登录三个页签；角色权限以说明矩阵展示，不提供编辑器。API Token 和用户组不出现在本版导航。

用户清单显示名称、来源、平台角色、状态、最后活动与授权数量；停用/删除说明影响会话、Grant 与审批。OIDC-only 用户不展示普通改密入口，admin 不得通过重置密码静默为其开通本地登录。

普通用户授权流程：选用户 → 选具体集群 → 选 namespace 范围/集群资源 → 选固定能力组合 → 选择专项能力与有效期 → 预览 → 保存。预览明确所有 namespace 是否包含未来对象、允许删除的范围、仍需真人审批的动作以及平台授权不保证集群 RBAC 放行。admin 无需自授权。

用户登录后，无授权显示“账号已登录，尚未分配集群权限”；有授权显示集群选择与能力范围。只读用户可以诊断并获得修复建议，修复按钮展示缺少的授权，不发送注定无权限的审批。Agent 越权时保留已有诊断，解释证据限制并提供联系管理员的明确路径。

读取他人对象的 admin 进入治理视图，显示操作者与 owner；隐藏发送消息、审批和继续执行入口。登录页启用 OIDC 时优先企业登录，本地账号入口保留；OIDC 故障不使本地应急入口消失。

## 13. 配置、加密与部署

OIDC 业务配置唯一来源为 DB Settings 的 auth 组，字段包括 enabled、display_name、issuer_url、client_id、client_secret、scopes、display/email/groups claim 映射、可选 allowed_groups。username 展示映射不改变身份主键。回调地址由静态 public_url + 固定 callback path 推导，IdP 精确登记；不接受请求 Header/参数动态决定可信来源。

静态配置承载 public_url、可信代理、TLS/受信任私有 CA、加密密钥和开发 HTTP 例外。默认验证 IdP TLS；不提供跳过证书校验的生产开关。Discovery/Token/UserInfo 请求均设超时、响应上限与受控重定向；服务端站外访问按部署网络策略限制，支持企业私有 IdP。

Client Secret 使用现有平台 Cipher 加密落库，密钥来自部署配置，API 不返回明文或密文。保存配置先校验并测试 Discovery，不在失败时覆盖可用配置；原子提交不可变 Provider 快照并使旧登录事务失效。普通名称/Claim 映射变化不注销既有会话；issuer/client_id 信任边界变化或禁用 OIDC 时，立即撤销旧 OIDC 会话，保留本地会话。Client Secret 轮换使旧未完成事务失效。

加密密钥轮换采用受控维护流程：备份并暂停敏感写入 → 旧密钥解密/新密钥重加密至可恢复副本 → 验证全部记录 → 原子切换数据与部署密钥 → 验证启动；失败保留旧密钥与备份，禁止先换密钥导致已有凭据不可读。本次复用现有 Cipher，缺少可恢复轮换工具时在交付中明确操作步骤和维护窗口，不虚构在线轮换能力。

生产采用同源 HTTPS；单副本约束写入部署清单，不提供“多副本只靠粘性路由就可高可用”的承诺。后续扩容必须一起设计认证 Session、登录事务、运行任务、审批与 SSE 的共享状态。

## 15. 数据升级与开发数据处理

沿用 internal/store 的递增迁移版本，SQLite/MySQL 均支持。先备份，记录源/目标版本；数据库 DDL 不一概假定可事务回滚，按方言设计检查点和幂等重跑。仅当完整步骤成功后推进版本。

本版不转换旧 operator 用户，也不把旧 */destroy Grant 自动映射为更宽的新权限。发现 operator 引用或缺失可信集群/主体/范围的旧 Grant 时，升级前检查明确阻止权限功能启用，并提示管理员备份后重置开发授权数据；不能静默升权或自动删整个数据库。角色/Grant 清理作为显式维护步骤留痕。

已有对话、报告没有可信 ClusterID/coverage 时只允许 admin 治理读取；不按 namespace 名称猜集群。新增用户身份唯一约束失败时明确报错，不把两个账号合并。users/authz/identities 的索引与一致性分别验证双数据库。

回退使用升级前备份并匹配旧版程序；启用 OIDC 后不能靠删 user_identities 表声称无损回退。恢复演练需证明本地 admin 可登录、授权没有扩大、报告对象关联有效；不要求建设通用历史账号迁移平台。

## 19. 实施记录

### 2026-11-07 第一批：身份撤销与资源授权基础

已落地：

- 文档迁入架构设计目录，文档中心增加导航。
- Store schema v9 增加 users.email/session_version 与 Grant.scope_type/resource_profile；SQLite/MySQL 共用 SQL 路径，旧 Grant 不自动转换。
- 用户密码、角色、状态变化与 session_version 在同一事务提交；旧版本更新拒绝，避免旧表单恢复旧密码。
- Token 每次验证检查 active/版本；改密、重置、停用、删除及角色变化撤销现有令牌，恢复账号不恢复旧令牌。
- 用户删除改为保留内部 ID 的逻辑注销；最后一个本地管理员按实际角色/状态/本地密码保护，不绑定固定用户名；并发停用也保留恢复入口。已有库无可用本地管理员时拒绝正常引导。
- 新增 ResourceGrantRequest、EffectiveAccess 和 Authorize 基础服务，按具体集群与 namespace/cluster 范围合并动作，检查动作前置关系，读取权威用户/Grant 状态；不接受旧通配、用户名或组 Grant 作为新模型授权。
- 增加认证撤销、并发管理员保护、旧表单覆盖、授权隔离/到期/撤权、v9 重跑与不隐式迁移测试，并更新用户管理 API 生命周期回归。

实施边界：新资源授权内核尚未切换到 HTTP Grant 管理、Agent/Scan/Report 与工具执行；现有三角色与旧 EffectiveScope 链路仍待替换，不能把新内核的单测结果当成线上门禁已经生效。OIDC、Cookie/CSRF、两角色清理、可信集群 Client 绑定、审批后复核和数据 coverage 尚未完成。后续须先完成这些调用方的统一切换，再启用新版授权交互，不同时合并新旧策略放行。

本批未修改前端；数据库真实 MySQL 集成需配置 AEGISOPS_TEST_MYSQL_DSN，未配置时不能宣称完成双数据库真机验收。测试门禁以本批交付结果为准，整体方案仍为实施中。

### 2026-11-08 平台入口与执行路径

平台入口已接入本地账号、OIDC、HttpOnly Cookie、CSRF 双重校验和 admin/user 两种角色。OIDC 使用 go-oidc、x/oauth2 和 Argo CD 的 claims 请求函数。企业身份按 issuer 与 subject 关联，绑定及解绑须验证本地密码。管理员在“用户与权限 → 企业登录”配置发现地址、客户端与准入组。

部署时将 platform.server.public_url 设置为浏览器使用的 HTTPS 站点根地址，在 IdP 登记该地址加 /api/v1/auth/oidc/callback。持久保存 AEGISOPS_ENC_KEY，供平台解密企业登录配置与集群凭据。本机 HTTP 调试须显式打开 platform.server.allow_loopback_http。服务端登录状态保存在进程内，重启后重新登录。

升级前备份数据库，盘点 operator 账号和旧 Grant，明确重新分配账号角色并撤销旧策略。v11 遇到仍有旧分配时终止升级。升级后先登记集群，在“授权委派”按普通用户和集群重新授权，再创建会话或发起体检。平台管理员无需资源 Grant。

会话数据范围在创建时按当时可读取的数据保守固定。范围缩小时限制旧正文，扩大后可新建会话。巡检与报告记录集群、目标范围与读/日志覆盖级别，下载走认证代理。无覆盖记录的存量产物走管理员治理入口。审批卡携带单次 ID，五分钟内有效，凭据变化与运行撤权均会阻止后续工具执行。

部署验收覆盖公司 IdP、真实集群 RBAC、数据库升级与回滚演练。当前阶段使用本地临时数据库和测试身份提供方。

### 2026-11-08 执行契约、数据覆盖与治理收尾

- kubectl fallback 支持明确资源的 get/describe、日志、scale/patch/rollout、删除、Node cordon/uncordon，以及明确 Pod 的已登记非交互诊断命令。多对象目标逐一核权，任一目标未覆盖时整体拒绝。
- 复合命令使用现有 mvdan shell AST 解析库校验，支持已授权 kubectl 命令组合、head/tail 截取，以及纯文字 heredoc 内的多文档 manifest。赋值、动态替换、重定向、未知程序或资源、外部凭据参数均返回无法核验目标。适用命令仍进入真人确认。普通 namespace 用户通过 create_resource 提交多文档清单。
- 所有受控 Kubernetes 请求和工具范围判定累计到会话 coverage.observed，包含实际解析出的资源及子资源。coverage.targets 保留更宽的保守执行边界，completeness=conservative，防止 kubectl 与工具内部诊断的数据依赖被低估。该保守范围参与读取核权，不将 observed 用作自动裁剪授权。
- 体检报告沿用 collection 采集质量账，Agent 的 ScanResult 摘要也包含 collection。namespace 报告按该 namespace 的完整读/日志覆盖级别核权，跨范围读取在 HTTP 请求前拒绝。报告列表、数量统计、正文、导出和下载共用范围判断。
- 管理员会话列表、跨用户改名/置顶/删除/取消、体检治理读取/取消、报告治理访问均在审计成功后执行。平台管理写入口先记录操作路径与动作，Grant 记录明确目标和策略，不记录凭据正文。
- 普通写操作的会话确认记录绑定登录认证会话与集群凭据版本，任一变化清空旧确认记录。审批请求、决定和参数指纹通过同一 ApprovalID 关联。

本地回归包括复合命令和多文档 manifest、跨用户审计故障阻断、报告 SQL 分页/统计/撤权、并发 coverage 累计，以及 OIDC issuer/audience/nonce/过期/未来签发时间/azp/subject/state/浏览器绑定错误路径。公司 IdP、真实集群及 MySQL 服务端仍属于部署验收。

高危 kubectl 操作在真人确认前采集明确目标的 UID/resourceVersion，恢复执行前再次读取并比对。目标被更新、删除或重建时拒绝旧确认。批量面板排除高危及要求逐次真人确认的专项操作。普通写操作已保存的会话确认在登录会话或执行凭据改变时清空。

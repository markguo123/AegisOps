# 用户决策交互设计

> **状态：部分废弃整改，2026-11-16（ADR-055）**。问题内容约束、选择不授权、安全与真人审批规则保留；独立展示状态、question.required/resolved 公共事件、常态轮询及历史工具卡拼装被 [25-方案-Chat流式输出与前端展示统一](25-方案-Chat流式输出与前端展示统一.md) 的 Interaction 与统一 reducer 替代。问答端点可复用，当前轮阻塞与重启失效边界保留。以下“已接通/本次验证”仅指旧实现，不代表新方案落地。


## 目标
沿用现有 Agent runtime，增加独立 ask_user_question 工具。借鉴 DSH 交互，不引入 Eino 或 Checkpointer。只在用户未指定且只读调查无法确定的关键决策上提问；不重复确认明确意图，不强制凑两个方案。

## 协议
问题包含 question 和 options（id、label、impact、recommended）。最多六个选项，允许零选项的自由输入；推荐项最多一个，不自动提交。问题最多 1000 字符，标题 120 字符，影响说明 500 字符，回答 2000 字符。
服务端生成问题 ID，绑定 session_id、turn_id。每会话最多一个待答问题。答案为 selected（option_id）、text（text）或 skipped，字段互斥。原子消费，拒绝重复、过期、跨会话及跨运行响应；无效响应不消费问题。
使用独立 GET/POST /sessions/{id}/question 协议，不复用审批答复和自动通过逻辑。GET 返回服务端当前待答状态，POST 原子接受答案。独立 question.required / question.resolved 事件通知界面查询状态；Web 仅在运行或有待答问题时每 1.5 秒兜底同步，空闲时不轮询，刷新后从服务端查询；已答记录通过既有工具观察事件与会话存储回放。认证与所有权检查复用现有规则。审计独立记录 decision.request / decision.response 的关联 ID 与状态，不记录回答明文。

## Web 与 CLI
Web 展示选择卡、影响说明、自由输入、提交和跳过；提交成功后才显示已回答。问题与脱敏答案可回放；刷新需以服务端待答状态判断能否提交。
CLI 交互模式展示 1 至 N 选项、自由输入入口和 0 跳过。非法编号重试；空输入不选推荐项。非交互模式返回 unavailable 未决状态，skip-permissions 不代替回答。

## 生命周期
当前运行等待答案，受上下文取消和最长五分钟期限控制。超时返回 timed_out，跳过返回 skipped，不执行依赖选择的动作。同一模型批次包含提问时，处理提问并丢弃其他调用，让模型依据答案重新生成操作。
不实现跨进程恢复。运行结束、取消、超时或重启后问题失效；历史记录仅供回放。

## 安全与提示词
选择方案不授权具体操作。后续写操作仍走原审批、RBAC 和 Executor。不得收集 Secret；问题、答案、会话与审计沿用统一脱敏和当前轮精确值脱敏。资源中的指令不可信。
修复与创建统一要求：先利用用户输入及只读证据；只有真实影响结果的分歧才提问。选项基于证据，不编造资源。跳过或超时后说明未决事项，不推断同意或重复逼问。

## 验收
覆盖选择、自由输入、跳过、非法参数、推荐项不自动提交、重复提交、过期及跨运行响应、取消、超时、非交互模式、刷新回放和提示词触发；验证原审批与 Secret 安全行为。完成后运行 Go 全量测试及 vet、前端类型检查与相关交互测试。

## 实施状态
已接通 Agent、服务端、Web 与交互式 CLI。问题与答案复用现有工具结果持久化与回放；非交互调用返回 unavailable。暂不实现草稿持久化、隐藏后重开卡片和跨进程恢复；这些不是当前可用功能。

## 架构冲突处理
- 旧修复规则强制至少两个方案：改为仅对有证据的真实分歧提问。
- 旧创建规则逐项追问并在审批前再次文字确认：先补只读证据，仅询问关键缺失信息；明确意图后直接提交具体提案审批，保留 dry-run 与 apply 门禁。
- 审批自动通过语义：普通决策使用独立协议，答案不能创建审批授权。
- 同批工具与决策的顺序：出现提问时仅执行该提问，模型收到答案后重新规划；未决状态阻止后续工具及批量审批。

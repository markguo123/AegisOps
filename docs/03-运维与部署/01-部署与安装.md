# AegisOps 部署与安装

本文面向 Linux 上的 Kubernetes 部署。安装前先选择运行方式，再按对应步骤操作。

**生产推荐：MySQL 保存业务记录与对象元数据，S3 兼容对象存储保存附件、报告文件和大型产物。** 已有 MySQL、S3/MinIO/Ceph 时直接接入；没有时由用户或基础设施团队先准备。AegisOps 只交付和维护应用 Chart，不安装、不维护中间件。日常升级、回滚只操作应用。

当前 Backend 为单副本，更新使用 Recreate，升级存在停机窗口。数据库和对象存储的可用性、备份及运维由服务提供方负责。本文不承诺未经真机验收的高可用、在线数据库降级或自动数据恢复。

## 1. 选择安装方式

| 场景 | 数据库 / 文件存储 | 推荐入口 |
| --- | --- | --- |
| 快速体验 | SQLite + 本地持久目录 | 项目根目录 `bash deploy/install.sh`（本地构建） |
| 生产，已有基础服务 | 外部 MySQL + S3 兼容服务 | `install.env` + `bash deploy/install.sh --env-file install.env`（只改一个文件） |
| 生产，无现成基础服务 | 用户先准备 MySQL + S3 兼容服务 | 按第 5 节完成依赖，再用 `install.env` 安装 |
| GitOps 或平台流水线 | 外部依赖，迁移可由平台执行 | 应用 Chart + 显式 values（原生 Helm） |

`db` 对象后端仅保留给兼容与轻量体验使用。生产不要默认将文件内容长期放在 MySQL。已有部署升级不会自动从 `db` 切成 `s3`，切换步骤见第 9 节。

会话消息、索引、状态与附件是不同数据：配置对象存储会将附件和文件产物交给它，不会自动把整份会话正文外置；当前 `platform.blobs.session_data=true` 被配置校验拒绝。

## 2. 安装前准备

快速体验需要：可用的 Kubernetes 集群、已配置的 kubectl、Docker 或 Podman，以及 Linux 上的 Bash、tar、sha256sum。无需预装 Helm、复制 values 或填写镜像标签；缺少 Helm 时会下载并校验固定的 Helm 3.17.3，缓存到 `${XDG_CACHE_HOME:-$HOME/.cache}/aegisops/`，不修改全局 PATH。

镜像分发是快速体验的硬前提：kind/k3d 集群由脚本自动 `kind load` / `k3d image import`；普通远程或多节点集群必须把镜像推送到节点可达的仓库，或提前把镜像分发到节点。部署端 Docker 缓存不会自动对集群可见。生产使用已安装或已缓存的 Helm 3，并准备服务与配置；安装已有镜像不需要容器构建工具。

首次源码构建需要能访问 Go 模块与 npm 依赖源；离线构建需预置依赖或改用已构建镜像。kind/k3d 载入镜像需要对应 CLI，推送镜像需要仓库登录凭据。缺失这些条件时脚本在构建前或构建后给出明确诊断，不会静默等待镜像拉取失败。

```bash
kubectl config current-context
kubectl cluster-info
kubectl get storageclass
```

确认以下条件：

- 安装身份能够创建目标命名空间、工作负载、Secret、PVC，以及应用所需的 RBAC。
- 集群节点能够拉取应用镜像；私有仓库配置 `imagePullSecrets`。
- 生产使用 PVC 时有可用 StorageClass；没有默认类就明确填写其名称。快速体验会自动检测默认类，没有时警告并使用临时存储。
- 生产入口使用 HTTPS；Ingress Controller、域名解析与证书由部署环境提供。
- 外部 MySQL 的数据库和账号已创建，字符集建议 utf8mb4，连接串必须包含 `parseTime=true`。
- 外部对象存储的桶已创建，应用账号具有该桶所需的对象读写权限。

配置和凭据放在源码目录外，避免更新代码时覆盖。生产只用 `install.env` 一个文件承载配置（凭据直接写其中，或引用已有 Secret）：

```bash
umask 077
mkdir -p "$HOME/.aegisops/deploy"
chmod 700 "$HOME/.aegisops/deploy"
```

镜像、Chart 和部署配置均需固定版本。示例中的镜像版本、域名、存储类必须替换为环境中的实际值，不使用 `latest` 作为生产版本。

## 3. 快速体验：一条命令

在检出的项目目录执行：

```bash
bash deploy/install.sh
```

无需先 chmod、安装 Helm、复制 values 或指定 TAG。脚本默认从**当前检出的源码**构建镜像，按集群类型分发后安装；不解析 GitHub Release，也不下载其它版本的安装包或镜像。未指定 TAG 时按当前提交生成构建标签，源码内容有未提交改动时需要显式 `--allow-dirty`。

快速体验使用 minimal（内嵌 SPA）、SQLite、本地文件后端和 HTTP NodePort，不安装 MySQL、MinIO。它会自动检测存储条件：

- 有默认 StorageClass：创建并使用持久卷。
- 没有默认 StorageClass：明确警告后使用临时卷，Pod 重建或升级会丢失体验数据。适合试用，不可当成生产安装。

首次体验不要求额外确认，完成后显示 NodePort 入口和初始用户名；交互终端会显示首次初始化口令，非交互输出仅给出本机读取命令。节点 IP 和 NodePort 必须从浏览器所在网络可达。

需要再次查看入口或口令时：

```bash
kubectl -n aegisops get service
kubectl -n aegisops get secret aegisops-credentials \
  -o jsonpath='{.data.password}' | base64 --decode
printf '\n'
```

初始用户默认为 `admin`；改密后 Secret 中的初始化口令不再代表当前登录口令。模型、集群和 OIDC 在登录后的页面配置。密码只在本机受控终端读取，不粘贴进工单、聊天或公共日志。

重复执行会重新构建（命中缓存）并以同一标签更新；镜像未变化时 Helm 更新为幂等操作，不重建 Pod。源码更新会产生新标签并重建 Pod：持久卷数据保留，临时存储数据丢失。脚本会在临时存储实例上明确提示该风险，不会用“同版本不重建”掩盖数据丢失。已有生产实例不会被快速体验覆盖。

需要自定义体验配置时再使用 `--profile=quickstart --values=<文件>`；预设在 `deploy/helm/aegisops/values-quickstart.yaml`。生产不要沿用体验配置中的 HTTP 登录开关。

**默认命令构建的就是当前检出的源码**，不会自动切分支、拉取代码或下载其它版本。需要固定版本时自行检出对应提交并指定 TAG；普通远程或多节点集群须设置仓库地址并开启推送。

## 4. 生产安装：已有 MySQL 与对象存储

> **首次安装三分钟版**
> 1. `cp deploy/install.env.example install.env && chmod 600 install.env`
> 2. 编辑 `install.env`：填 `IMAGE`/`TAG`、`MYSQL_DSN`（或 `MYSQL_SECRET`）、`BLOBS_*`（或 `BLOBS_SECRET`）、域名与 `STORAGE_CLASS`。
> 3. `bash deploy/install.sh --env-file install.env --yes`
>
> 常规部署**只改 `install.env` 一个文件**。只有复用已有 PVC、接管旧实例、调整资源、固定镜像 digest、
> 复用加密凭据 Secret 这类「依赖集群现状」的高级项，才去改 Helm values（见 4.5 节）。

### 4.1 配置模型：一个文件就够

`install.sh` 和原生 Helm 是两条安装路径，各自只需要一个配置文件：

| 安装路径 | 唯一需要改的文件 | 说明 |
| --- | --- | --- |
| `deploy/install.sh`（推荐） | `install.env` | 脚本把其中的值转成 Helm `--set`，覆盖内置预设；**不需要改 `values.yaml`** |
| 原生 `helm install/upgrade` | `values.yaml`（或私有 values） | 直接交给 Helm；不使用 `install.env` |

`install.sh` 会合并三层来源，后写入的覆盖先写入的：

1. 内置预设 `values-<profile>.yaml`（脚本自带，不用改）；
2. 显式传入的 `--values`（可选，只用于覆盖脚本未暴露的字段）；
3. CLI `--KEY=VALUE`、环境变量、`install.env` → 转成 `--set`，最后生效。

也就是说，优先级是 **CLI > 环境变量 > `install.env` > 内置默认**，且 `--set` 覆盖 `--values` 与预设。
对正常生产安装，**只改 `install.env` 一个文件**；`values.yaml` 只在你直接使用 Helm 时才需要改。

### 4.2 准备数据库与对象存储凭据

外部 MySQL 与 S3 服务由你或基础设施团队提供（见第 5 节）。凭据有两种接入方式，二选一：

**方式 A（推荐，仍只改一个文件）**：把连接串和对象存储参数直接写进 `install.env`，脚本会自动创建
标准命名的 Secret（`<release>-mysql`、`<release>-s3`）：

- `MYSQL_DSN`：MySQL 连接串，必须含 `parseTime=true`；
- `BLOBS_ENDPOINT/BLOBS_REGION/BLOBS_BUCKET/BLOBS_ACCESS_KEY/BLOBS_SECRET_KEY/...`：对象存储参数。

**方式 B（自管 Secret）**：先用 kubectl 建好 Secret，再在 `install.env` 里只填名字：

- `MYSQL_SECRET=<你的 MySQL Secret 名>`（键为 `dsn`）；
- `BLOBS_SECRET=<你的 S3 Secret 名>`（键为 `AEGISOPS_PLATFORM_BLOBS_*`）；
- 可选 `MIGRATION_SECRET=<DDL 迁移账号 Secret 名>`，与运行账号分离。

`MYSQL_DSN` 与 `MYSQL_SECRET`、`BLOBS_ENDPOINT` 与 `BLOBS_SECRET` 各自二选一，同时给出会被拒绝。
下面给出方式 B 的自建 Secret 示例；使用方式 A 时整段可跳过。

先创建命名空间（已存在则跳过创建）和受限凭据文件。文件内容通过编辑器填写，不把真实口令放进 CLI 参数：

```bash
kubectl create namespace aegisops
umask 077
vi "$HOME/.aegisops/deploy/mysql.env"
vi "$HOME/.aegisops/deploy/s3.env"
```

`mysql.env` 使用以下单行环境变量格式。去掉尖括号，填实际值；连接串必须包含 `parseTime=true`：

```dotenv
dsn=<用户>:<口令>@tcp(<MySQL主机>:3306)/<数据库>?parseTime=true&charset=utf8mb4
```

`s3.env` 为环境变量文件，键名与格式如下：

```dotenv
AEGISOPS_PLATFORM_BLOBS_DRIVER=s3
AEGISOPS_PLATFORM_BLOBS_ENDPOINT=<对象存储主机>:<端口>
AEGISOPS_PLATFORM_BLOBS_BUCKET=aegisops
AEGISOPS_PLATFORM_BLOBS_REGION=us-east-1
AEGISOPS_PLATFORM_BLOBS_ACCESS_KEY=<应用访问密钥>
AEGISOPS_PLATFORM_BLOBS_SECRET_KEY=<应用秘密密钥>
AEGISOPS_PLATFORM_BLOBS_USE_TLS=true
AEGISOPS_PLATFORM_BLOBS_PATH_STYLE=true
AEGISOPS_PLATFORM_BLOBS_CREATE_BUCKET=false
```

`ENDPOINT` 不含 `http://` 或 `https://`；是否启用 TLS 由 `USE_TLS` 指定。集群内私有 MinIO 的 ClusterIP 接入可按现场使用 `false`，公网或跨网络接入推荐 TLS。不同 S3 服务的 `PATH_STYLE` 要按其要求填写。

```bash
kubectl -n aegisops create secret generic aegisops-mysql \
  --from-env-file="$HOME/.aegisops/deploy/mysql.env"
kubectl -n aegisops create secret generic aegisops-s3 \
  --from-env-file="$HOME/.aegisops/deploy/s3.env"
```

生产可将 DDL 迁移账号与运行账号分开：`install.env` 用 `MIGRATION_SECRET=<Secret名>`（裸 Helm 时对应 `database.migrationSecret`），两个 Secret 都使用 `dsn` 键。留空时迁移任务复用运行连接串，该账号必须具有本次迁移所需权限。

### 4.3 填写 install.env 并安装（常规部署只改这一个文件）

```bash
cp deploy/install.env.example install.env   # 建议放到源码目录之外，如 ~/.aegisops/deploy/
chmod 600 install.env                        # 含凭据时
vi install.env
```

完整字段与逐行中文说明见 `install.env.example`。常规生产至少确认以下几项：

```dotenv
PROFILE=production
IMAGE=<仓库地址>/aegisops
TAG=<已发布的固定版本>
FORM=standard
NAMESPACE=aegisops

STORE_DRIVER=mysql
# 方式 A：脚本创建 Secret
MYSQL_DSN=<用户>:<口令>@tcp(<MySQL主机>:3306)/<数据库>?parseTime=true&charset=utf8mb4
# 方式 B：引用已有 Secret（与 MYSQL_DSN 二选一）
#MYSQL_SECRET=<已存在的MySQL Secret名>

BLOBS_BACKEND=s3
BLOBS_ENDPOINT=<对象存储主机>:<端口>
BLOBS_BUCKET=aegisops
BLOBS_ACCESS_KEY=<应用访问密钥>
BLOBS_SECRET_KEY=<应用秘密密钥>
BLOBS_USE_TLS=true
BLOBS_PATH_STYLE=true
# 方式 B：引用已有 Secret（与 BLOBS_ENDPOINT 二选一）
#BLOBS_SECRET=<已存在的S3 Secret名>

PERSIST_REPORTS=true
STORAGE_CLASS=<StorageClass>
PUBLIC_URL=https://<实际域名>
INGRESS_HOST=<实际域名>
INGRESS_CLASS=<IngressClass>
INGRESS_TLS_SECRET=<已有TLS Secret>
```

然后一条命令完成构建、推送（如需）与安装：

```bash
bash deploy/install.sh --env-file install.env --yes
```

已有 CI 构建并推送好的镜像时，在 `install.env` 里写 `BUILD=false`，脚本自动复用，无需其它参数。

**哪些配置不该写进 install.env**：复用你已有的 PVC（`persistence.existingClaim` /
`existingReportsClaim`）、调整 `resources`、接管旧实例（`adoption`）、固定镜像 `digest`、
复用已有加密凭据 Secret（`credentials.existingSecret`）等，属于依赖集群现状的高级配置，
由运维工程师按现场填写 Helm values（`--values` 叠加或直接改 `values.yaml`）。这样通用
`install.env` 模板不会被环境特有值污染。见 4.5 节与 `values.yaml` 内的中文注释。

没有 Ingress 时可将应用入口接到环境已有的 HTTPS 代理，但仍需设置正确的 `PUBLIC_URL`。

### 4.4 构建源的加速 / 代理怎么配

源码构建时的依赖下载默认走 Go 官方代理（`proxy.golang.org`）、npm 官方源（`registry.npmjs.org`）
和 `files.m.daocloud.io` 的 kubectl mirror。这些站点（尤其 `proxy.golang.org`、`gcr.io`）在内网或
国内直连时可能卡住或不可达。三种配置按键方式等价（**优先级 CLI > 环境变量 > `install.env` > 内置默认**）：

- 在 `install.env` 里写（推荐，不把敏感值放命令行）：

  ```bash
  GOPROXY=https://goproxy.cn,direct
  NPM_REGISTRY=https://registry.npmmirror.com
  KUBECTL_DOWNLOAD_BASE=https://files.m.daocloud.io/dl.k8s.io/release
  KUBECTL_VERSION=v1.29.15
  ```

- 导出同名环境变量后运行；或直接加在命令尾部，如
  `bash deploy/install.sh ... --GOPROXY=https://goproxy.cn,direct --NPM_REGISTRY=https://registry.npmmirror.com`。

`KUBECTL_DOWNLOAD_BASE` 的根路径目录结构需与 `dl.k8s.io/release` 一致；气隙现场推荐先把 kubectl
二进制放进 `deploy/kubectl/`（离线投递优先，构建全程零外网，见 `deploy/kubectl/README.md`）。

重复构建（改了几行 Go 或前端代码后重建）默认会重跑 `go mod download` / `npm ci`。BuildKit 本身会把
层缓存留在本机，命中即可复用少变依赖层。加 `--cache-build`（或 `CACHE_BUILD=true`）时脚本会按驱动处理：
`docker-container` 等支持本地导出的驱动把缓存落到 `${XDG_CACHE_HOME:-$HOME/.cache}/aegisops/buildkit`
（可用 `BUILD_CACHE_DIR` 覆盖）；Docker 默认的 `docker` 驱动不支持 `type=local` 导出（否则报
`Cache export is not supported for the docker driver`），会自动降级为内联缓存，不会让构建失败。
podman 不支持该缓存导出，检测到时会忽略并提示。

### 4.5 原生 Helm 安装（可选路径，改 values.yaml）

不用 `install.sh`、直接使用 Helm 时，才编辑 `deploy/helm/aegisops/values.yaml`
（字段中文注释已写在文件里）。常用必改项：

```yaml
image:
  repository: <仓库地址>/aegisops
  tag: <已发布的固定版本>
web:
  repository: <仓库地址>/aegisops-web
  tag: <已发布的固定版本>
database:
  driver: mysql
  existingSecret: <MySQL Secret名>
blobs:
  driver: s3
  existingSecret: <S3 Secret名>
ingress:
  enabled: true
  host: <实际域名>
  tlsSecret: <已有TLS Secret>
persistence:
  storageClass: <StorageClass>
```

复用已有 PVC、接管旧实例、调整资源等高级配置也在 values 中完成：

```yaml
persistence:
  existingClaim: <已有/data卷PVC名>
  existingReportsClaim: <已有/reports卷PVC名>
```

然后安装（使用你自己的私有 values 文件，不要提交真实凭据）：

```bash
helm upgrade --install aegisops ./deploy/helm/aegisops \
  --namespace aegisops --create-namespace \
  -f "$HOME/.aegisops/deploy/values-production.yaml" \
  --wait --wait-for-jobs --timeout 15m
```

原生 Helm 路径不需要 `install.env`；两种方式管理同一个 Release 时，改用其中一种，不要混用。

项目不提供公共镜像，生产镜像只有两个来源：本脚本从当前源码构建并推送，或你的 CI 构建后推送。

默认生成的 `aegisops-credentials` Secret 包含初始管理员密码和加密密钥，升级复用、卸载保留。务必备份；丢失加密密钥不能靠重新生成恢复已加密的模型、集群等凭据。GitOps 可用 `credentials.existingSecret` 引用自行管理的 Secret，需包含 `key`（64 位十六进制字符串）和 `password`。

## 5. 没有现成数据库和对象存储怎么办

AegisOps 安装器只安装应用。项目不自研、封装或维护 MySQL/MinIO Chart，也不承诺替用户维护这些服务。生产所需的数据库和对象存储由用户、基础设施团队或服务供应商准备，完成后按第 4 节接入。

| 依赖 | 可以采用的来源 | 交付给应用的内容 |
| --- | --- | --- |
| MySQL | 企业现有数据库、托管 MySQL，或依官方 Operator 文档部署 | 地址、数据库、应用账号、迁移账号（可选）、可信 CA（按环境） |
| S3 兼容对象存储 | 企业现有 S3/MinIO/Ceph、云对象存储或受支持的供应商产品 | endpoint、桶、region、应用访问凭据、TLS 和寻址方式 |

MySQL 在 Kubernetes 上的官方入口是 [MySQL Operator 安装文档](https://dev.mysql.com/doc/mysql-operator/en/mysql-operator-installation.html)，其中提供 Helm 与清单安装方式。Operator、MySQL 集群的版本、存储、备份和升级应由基础设施团队按其要求维护，不与应用 Release 捆绑。

**MinIO 社区仓库已于 2026-04-25 归档。** 不应把历史社区 Chart 或旧镜像当作本项目承诺支持的生产依赖。可参考[上游仓库状态](https://github.com/minio/minio)；如果选择供应商当前的 AIStor 产品，参考[官方 Kubernetes 安装文档](https://docs.min.io/aistor/installation/kubernetes/)，并确认其许可、支持和资源要求。AIStor 与原社区版本不是可以不加区分地替换的交付选项。

基础服务准备完成后，先从应用实际运行的网络验证连通，再创建第 4 节中的 Secret。生产应用账号应使用受限权限，不向应用提供 MySQL root 或对象存储管理员账号。

如果只是临时试用、尚不具备生产依赖，使用第 3 节的 SQLite + 本地目录体验模式。不要为了跳过依赖准备而把生产数据长期存入临时卷。

## 6. 预演、纯 YAML 与离线部署

Helm 模板是唯一应用模板来源。需要检查或交给平台审核时，先生成本地预览：

```bash
bash deploy/install.sh --env-file install.env \
  --dry-run --render-dir="$HOME/.aegisops/deploy/render-preview"
```

预览只包含应用资源，不生成数据库或对象存储安装资源。预览目录为 700、文件为 600；其中可能包含生成的 Secret，必须按凭据文件保管。随机凭据导致离线预览不保证逐字一致；需要确定性渲染时使用明确的现有 Secret 引用。

预演不会检查实际连通性、RBAC、存储供给或镜像可拉取性。**不要将预览文件直接 `kubectl apply` 成为第二套安装方式。** 正式安装使用同一 values 调用 Helm；静态 YAML 用于审查和平台集成，后者需要自行承担凭据和迁移任务的生命周期。

离线环境需提前交付应用 Chart、对应应用镜像与 Web 镜像。修改应用 Chart 的镜像仓库引用和 `imagePullSecrets`，将镜像导入内部仓库后再安装。外部数据库和对象存储按各自供应商流程单独准备。安装已有镜像不需要源码构建，不依赖现场拉取 Chart 依赖。

## 7. 日常升级与镜像回滚

升级前保存当前 values、应用版本和 Helm revision，并完成第 8 节备份。

- 用 `install.sh` 的实例：只改 `install.env` 里的 `TAG`，重新执行
  `bash deploy/install.sh --env-file install.env --yes`；脚本按新 TAG 取镜像并走同一个 Release。
- 用原生 Helm 的实例：修改私有 values 中的固定镜像版本后重新执行 `helm upgrade`。

`standard` 模式同时更新 Backend、Web；Backend 与 Web 均可通过各自的 `digest` 固定镜像内容；只设置 Backend digest 不会自动推导 Web 镜像版本。

```bash
helm history aegisops -n aegisops
helm get values aegisops -n aegisops > "$HOME/.aegisops/deploy/previous-values.yaml"
helm upgrade aegisops ./deploy/helm/aegisops \
  -n aegisops -f "$HOME/.aegisops/deploy/values-production.yaml" \
  --wait --wait-for-jobs --timeout 15m
```

`upgrade.sh` 是便利入口，状态、历史与回滚使用原生 Helm，不再维护私有成功版本账本。查看其 `--help` 获取参数；直接使用上述 Helm 命令始终可用。

回滚应用时，先在 `helm history` 中选定已知正常且数据库兼容的 revision：

```bash
helm rollback aegisops <目标revision> -n aegisops \
  --wait --wait-for-jobs --timeout 15m
```

回滚只针对应用 Release，不操作外部 MySQL 或对象存储，也不会撤销已完成的数据库迁移。紧急通过 Deployment 切换镜像后，应同步 Helm/GitOps 中的期望版本，避免下一次调谐覆盖紧急变更。

每次发布会进入迁移流程，但 `schema_migrations` 已记录的步骤会跳过；同一 schema 版本并非每次都改表，更不是升级 MySQL 软件。MySQL 的迁移由按 Helm revision 命名的 Job 执行，Pod init 只等待 schema 就绪，服务以 `--skip-migrations` 运行。SQLite 由 init 执行幂等迁移。

使用平台流水线独立迁移时设置 `migration.mode: external`，应用 Chart 不创建 MySQL 迁移 Job；须先在受控任务中运行新镜像的 `AEGISOPS_PLATFORM_BLOBS_DRIVER=off aopsctl db migrate --config /etc/aegisops/config.yaml`，然后发布应用。该任务必须挂载相同平台配置、正确数据库 Secret，并由流水线避免并发迁移。`off` 仅作用于本次数据库命令，避免尚未注入对象存储配置时触发 S3 配置校验；不会改变应用的生产 S3 后端。Chart 自带的迁移和 schema 检查容器会自动设置此覆盖。

历史迁移并非全部向后兼容，例如 v11 包含角色调整和 Token 撤销。MySQL DDL 也不保证随事务整体回滚。不能将“旧镜像 Ready”视为所有业务和旧数据均已恢复；不兼容升级需要按版本说明及备份恢复流程处理。

快速体验默认从当前源码本地构建；生产默认安装已有镜像，不自动构建或推送。生产需要源码构建时显式开启 `BUILD=true`、`PUSH=true`（远程/多节点集群必须推送）。选择构建推送时应使用新的固定标签，避免覆盖仓库历史版本。配置的 TAG 原样使用；未指定时快速体验按当前提交生成标签，`--allow-dirty` 只解除内容改动阻断。推荐用 `bash deploy/install.sh`，无需手工授可执行权限。

## 8. 备份、恢复与卸载

备份至少包含：MySQL 一致性备份、对象存储文件及元数据、应用加密 Secret、外部服务访问凭据、values 与镜像版本。需要本地目录后端或 SQLite 时，还要备份对应持久卷。

备份由数据库/存储运维流程完成，不提供“复制 PVC 就一定一致”的承诺。记录备份时间点，验证数据库与桶中的对象引用相互匹配；恢复演练应在隔离环境中执行。

保存应用加密凭据的本机命令：

```bash
umask 077
kubectl -n aegisops get secret aegisops-credentials -o yaml \
  > "$HOME/.aegisops/deploy/credentials-backup.yaml"
```

这份文件是敏感明文等价物，不提交 Git。自管 Secret 或不同 Release 名时替换名称；外部 MySQL/S3 的应用访问 Secret 也须分别保存。

恢复顺序为：停止应用写入 → 恢复相容的数据库及对象存储 → 恢复原加密/访问 Secret → 指定对应应用镜像与 values → 验证登录、历史会话、附件下载及报告。不要启动新服务先生成一套不同的加密密钥。

```bash
helm uninstall aegisops -n aegisops
```

卸载应用不会删除外部数据库或对象存储。保留的 PVC 与凭据需要由管理员显式处理；不要为“重装干净”删除整个命名空间。复用保留的卷与凭据时用 Chart 提供的 `existingClaim`、`existingReportsClaim`、`existingSecret` 引用，避免依赖隐式接管。

## 9. 旧部署迁移与对象后端切换

旧 `install.sh` 管理的实例不会自动转交 Helm。它们的 Deployment selector、资源归属和 Secret 命名可能不同，不能靠覆盖安装完成迁移。

先保存数据库、桶/本地文件、加密密钥、管理员初始化凭据与旧配置。将旧加密和管理员值通过受限文件合并为新 `credentials.existingSecret`，键分别为 `key`、`password`；数据库和 S3 的引用也需显式对齐。兼容 env 文件导入只在目标 Secret 不存在时创建，不会覆盖已有值；轮换凭据应显式管理对应 Secret，不要靠重跑安装替换。保留原数据卷、报告卷时填写 `persistence.existingClaim` 与 `persistence.existingReportsClaim`。

在停机窗口中停止旧应用，按资源清单评审 Helm 接管方案。旧 Deployment 的 selector 与新 Chart 不同时，需只删除旧 Deployment 后重建，保留 PVC、数据库与原始 Secret；其它冲突资源也必须逐项核对。

经过备份与人工评审后，手动接管配置可显式设置：

```yaml
adoption:
  scriptManaged: true
credentials:
  existingSecret: <包含原key和password的新Secret>
persistence:
  existingClaim: <原data卷名>
  existingReportsClaim: <原reports卷名>
```

`adoption.scriptManaged` 仅解除已确认的旧脚本归属阻断，且要求明确保留凭据和 data 卷，不会自动迁移 selector、数据或对象内容。保留资源需要变更 Helm 归属时，由管理员在人工确认的直接 Helm 操作中使用 `--take-ownership`；安装器不会默认加此参数。不要删除命名空间，也不要用接管开关绕过存储驱动或对象后端的迁移校验。

若从 `db` 或 `dir` 切到 `s3`，应在旧实例仍可读取源对象时准备目标存储，使用 `aopsctl blobs migrate --help` 核对参数，先 dry-run、再迁移，并运行 `aopsctl blobs verify --strict`。命令必须读取实际平台配置，不可漏掉 `--config` 而连接一个空的默认库。迁移、校验成功且完成备份后才改变部署引用；不能只改 `blobs.driver` 就宣称历史附件已搬迁。

## 10. 排障与企业配置

```bash
helm status aegisops -n aegisops
kubectl -n aegisops get pods,jobs,pvc
kubectl -n aegisops get events --sort-by=.lastTimestamp
kubectl -n aegisops logs deployment/aegisops-server --tail=100
```

| 现象 | 优先检查 |
| --- | --- |
| PVC Pending | StorageClass、容量、provisioner；WaitForFirstConsumer 在消费 Pod 调度前 Pending 可正常 |
| ContainerCreating | Pod Events、CSI 日志、卷挂载与文件权限，不凭 RWO 名称直接判定根因 |
| init 一直等待 schema | 当前 revision 的 migrate Job 日志、数据库连通和 DDL 权限 |
| 迁移 Job 失败 | 保留现场日志，先确认是否存在不兼容旧授权数据，不要循环删除重跑掩盖问题 |
| CLI 报 `platform schema is at version 0` | 先确认携带 `--config /etc/aegisops/config.yaml`；Pod 的 HOME 是临时目录，漏掉配置会连到新的默认 SQLite 空库，并不证明生产 MySQL 没迁移 |
| Ready 但附件 503 | 对象存储桶、TLS、账号权限与网络；文件后端可降级，应用 Ready 不代表桶可用 |
| HTTP 页面能开但无法登录 | 生产 Secure Cookie 要求 HTTPS；仅体验模式显式允许 HTTP |
| 镜像更新后仍是旧版本 | 固定标签是否被复用、pullPolicy、节点缓存以及 Backend/Web 版本是否一致 |
| `ImagePullBackOff` / `ErrImagePull` | kind/k3d 是否成功载入镜像；远程集群是否已推送到节点可达仓库、`imagePullSecrets` 与网络是否可用。部署端 Docker 缓存默认对集群不可见 |
| 构建成功但脚本退出 | 查看脚本在构建后打印的“未检测到 kind/k3d…节点可达”诊断；远程集群需 `--IMAGE=<仓库>/aegisops --PUSH=true` |

企业 OIDC 私有 CA 使用 Secret 的 `ca.crt` 键，并在应用 values 设置 `auth.oidcCASecret`：

```bash
kubectl -n aegisops create secret generic aegisops-oidc-ca \
  --from-file=ca.crt=/受控路径/企业CA.pem
```

仅已确认 IdP 兼容性缺陷时启用 `auth.oidcDisablePKCE` 或 `auth.oidcAllowMissingNonce`；默认保持关闭。它们不替代正确 CA 信任、回调地址和 IdP 客户端设置。

启用写工具 RBAC 使用 `writeAccess: true`。这只授予 Kubernetes 能力范围，不绕过产品的真人审批、Secret 读取约束或 Executor 策略。

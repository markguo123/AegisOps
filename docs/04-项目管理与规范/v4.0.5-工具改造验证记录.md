# v4.0.5 工具改造验证记录

基线为 `main` 的 `6485ece`，候选分支为 `DEV-v4.0.5`。原设计见 [方案 33](../02-架构与设计/33-方案-全量工具优化与改造.md)。

## 目录与调用迁移

| 原入口 | 模型目录入口 | 迁移行为 |
| --- | --- | --- |
| `get_pod`、`get_node`、各工作负载查询、Service、Endpoints、PV/PVC、StorageClass、Namespace、ConfigMap 单查 | `get_resource` | 旧名已下线。命名空间 GET Pod 只有明确 NotFound 才查找候选。 |
| `get_pods`、`get_nodes`、`get_configmaps`、`get_resources`、`get_endpointslices` | `list_resources` | 标准客户端直接向 Kubernetes 发送选择器、页大小和续页令牌。旧名已下线。多个旧入口覆盖同一列表能力时取仍启用的并集。 |
| `scan_pod`、`diagnose_pod`、`diagnose_node`、`diagnose_workload` | `diagnose_resource` | 继续使用 ScanService。Node 和工作负载输出仅报告目标诊断范围与 Finding。 |
| `get_logs`、`get_previous_logs` | `get_logs(instance=current/previous)` | Agent 调用显式指定实例。旧 `get_previous_logs` 只识别为禁用配置，日志调用必须指定实例。 |
| `get_secret_info` | `get_secret_info` | 采用方案的 16 项目录路径，独立复用元数据白名单和命名空间约束。 |
| `get_secret_value` | `get_secret_value(operation=check_nonempty/compare_config/read)` | 缺少 operation 在审批前返回 INVALID_ARGUMENT，旧历史仍可读取。 |

运行时只注册规范入口，历史结果按原名展示。旧禁用项继续限制对应 kind 或实例。

同一个 Kubernetes 列表游标须搭配原查询使用。游标绑定集群、资源、命名空间、选择条件和页大小，在进程重启后失效。分页继续经过当前请求鉴权。用户可以用 `list_resources(kind=Pod, ownerKind, ownerUID)` 核对控制器归属，Deployment 的归属通过 ReplicaSet UID 链核对。启用全部功能的预期内置目录为 16 项，外部 MCP 和独立 CLI MCP 单独计数。

## 回退与发布门槛

- 回退按已验证版本执行，保留 Secret 操作必填、UID 取证和安全修复。历史展示沿用原工具名和已脱敏结果。出现授权或归属异常时，通过规范名关闭受影响的能力。
- ClusterRoleBinding 复合命令测试已按确认口径更新，并覆盖预检、实际请求与撤权。
- 当前落地覆盖本地实现及测试。真实集群验收仍需覆盖撤权后续页、同名重建、组件缺失、发布就绪但原症状仍存在、MCP 超时和巡检引用过期。性能对照需统一模型、凭据和故障数据后记录工具命中、模型轮数、API 请求数、输入 token 和耗时。未形成真实环境对照数据。

## 本地验证口径

以同一工作环境分别运行候选和基线的 `go test ./...`。两次均报告 149 条失败记录（含子测试），按测试名对比没有新增失败。失败集中在 MySQL DSN 与模型配置相关测试、复合命令权限用例和 CLI 依赖方向检查。现有架构断言报告 CLI 直接依赖 `internal/audit`。对这些用例保留原约束，发布时应记录独立修复或明确裁决。

定向回归包括同名 Pod 的事件 UID、禁用单查 kind 后的 Schema 分派、旧名无法执行、规范名授权与撤权、查询游标约束、缺省 Secret 操作、MCP 结构化结果和写入途中断开的状态。

定向 Go 回归、`go vet ./...`、Web 类型检查和构建通过。Web 全量测试在候选和基线均为 254 通过、11 失败，失败用例同属 SettingsView，聊天和工具卡片相关用例通过。

本次下线旧名后的全量 Go 复跑额外出现一次 TestKubectlAuthenticatesThroughGateway 失败，该用例单独重跑通过。定向工具、授权、诊断和历史回归与 go vet 均通过。

## 后续阶段实施

1. **目录与会话契约。** Native 与 shim 使用同一套按当前授权快照裁剪的 Schema。调用时仍执行实时鉴权。新工具事件在会话、SSE 与审计中记录契约版本，旧记录缺省；会话首次切换契约时清除已有写审批缓存。
2. **定向采集。** Node 诊断只 GET 目标节点，明确未采集 Pod 与事件。工作负载先 GET 精确目标，在所属命名空间读取关联数据，按控制器 UID（Deployment 经 ReplicaSet）筛选 Pod 和事件。只启用适合这些证据的规则。输出覆盖对象和采集质量，不发布环境健康分。
3. **结果呈现。** 模型、CLI、Web 实时事件、会话回放和审计共用部分结果状态。使用“Pod 可读、Events 被拒”用例核对模型观察、CLI 事件和存储快照，并验证 Web 卡片、审计记录和 Markdown 导出都保留部分结果状态。
4. **代码清理。** 移除已无调用方的工具名枚举、旧 kind 分派和节点指标工厂分支；Secret 审批模式仅在配置层接收历史值，注册层不再转发无效参数。
5. **发布验收。** ClusterRoleBinding 读取口径已确认，集群级 read 可读，namespace 用户无权读取。真实模型与集群对照需要已授权的模型、集群和故障样本。现有自动化 fixture 支持本地验证，不代替真实环境性能数据。

本轮阶段回归的全量 Go 失败名称与基线一致，共 149 条（含子测试）。Web 类型检查通过，聊天、工具卡片与 Markdown 导出定向测试 24 个全部通过。

# P5 真机验收步骤

使用独立测试部署、MySQL 和对象存储。准备平台管理员、用户甲、用户乙，以及两个测试集群。两个集群均准备 payment 和 edge-system namespace。不要使用生产报告、真实凭据或生产集群。记录构建版本和部署副本数。

## 报告保留预览

1. 在两个测试集群分别生成 Markdown 和 JSON 报告，包含不同所有者。选一个集群和一种格式，准备三份早于截止时间、一份晚于截止时间的报告。可使用独立测试库中的历史报告或测试夹具，保持报告与对象引用完整。
2. 管理员打开「配置中心 → 保留」（也可由报告页快捷入口跳转），选该集群和格式，设置保留天数为 1、最近份数为 2。预期共 4 份、按天数和份数保护 2 份。若其余两份来自新版成功结束的 Web 体检，则可清理 2 份。存量报告会显示在「无法确认扫描终态」中。把最近份数提高到 4，预期可清理为 0。切换集群或格式应清空旧结果，重新计算只包含新范围。
3. 打开浏览器开发者工具的网络面板，确认预览请求为 GET /api/v1/report-retention/preview。普通用户登录看不到报告页入口和配置中心「保留」页签。用普通用户会话请求同一 URL，预期 403。管理员将 days 改成 0，预期 400。
4. 关闭预览后重新打开报告。预期报告数、下载结果和对象引用计数保持一致。若结果不符，保存请求参数、响应和筛选后的报告 ID。

## 长期记忆验收

先用管理员在配置中心启用 Memory，然后在 Chat 会话标题处打开「诊断记忆」。明确填写工作负载、主 namespace 和相关 namespace。首版要求提问包含完整工作负载名，例如 payment-api，且记忆范围与本轮授权相符。

1. 给甲授权集群 A 的 payment 和 edge-system 读权限。甲在 Chat 明确保存「payment-api 发布期间出现 502 时，对齐网关报错与旧 Pod 退出时间」，确认两个 namespace。取消保存一次，再重复确认同一个提交，预期最终仅有一条记录。
2. 甲在集群 A 新开 Chat 问 payment-api 502。预期展示记忆引用，并用当前证据排查。准备报错早于发布的测试数据，确认回答会排除旧解释。切到集群 B 发同样问题，预期无引用。
3. 给乙同样的集群 A 授权并发同样问题，预期看不到甲的记忆。撤销甲对 edge-system 的权限，在已有会话继续提问，预期从下一次模型请求起停止召回。恢复权限后修改记忆，验证下轮采用新版本，再执行遗忘，验证新会话与旧会话下一轮均不再召回。
4. 用专门设置的无害哨兵值测试 Secret 诊断。确认 ModelOnly 仅出现在授权的当前模型请求中，哨兵值不出现在记忆 API、SSE、对话历史、摘要、审计或记忆表。检查模型请求使用的是当前对话所选模型。

### 从诊断结论保留经验

1. 用启用记忆的账户完成一轮有明确复用价值的诊断，例如通过对齐网关报错和旧 Pod 退出时间定位 502。若最终结论给出结构完整的建议，预期结论下出现一次「保留这条排查经验」。普通检查、未完成的轮次和 Secret 诊断轮应无此按钮。
2. 点击按钮，或在有建议的会话中输入「记住刚才的排查方法」。预期打开带集群、命名空间、工作负载与经验的草稿。关闭草稿再打开记忆列表，预期记录数不变。重新打开草稿，核对范围后点击「确认保存」，预期只新增一条。
3. 新建会话并提到同一工作负载，准备与历史根因冲突的本次证据。预期 Agent 按当前证据复核。对确需写操作的独立测试工作负载拒绝本轮审批，核对执行记录与资源状态，预期未发生改动。

## 调度、审计与对象回收验收

使用双副本指向同一测试数据库和对象存储。仅对可删除的测试数据启用策略。启用后下一次调度检查即处理第一批，检查间隔约一分钟，此后按该策略的执行周期处理，每批最多 200 份。为了当天验收，可在独立测试数据库中，仅将新版成功 Web 扫描产出的测试报告 created_at 调早两天，保留 retention_finalized 原值，通过页面配置 1 天保留。

1. 带旧版 enabled=true 和 archive 配置升级，跨过一次调度周期。预期报告数量不变，策略需重新预览和激活。
2. 激活一个集群及一种格式的策略。预期仅移除符合年龄和最低份数条件的终态报告。活动依赖或无法确认生命周期的报告应保留。检查策略卡片的上次运行时间、数量及对应审计。审计 action 为 report.retention.run 或 report.retention.delete，同一批使用同一 request ID。
3. 准备共享同一对象的两份报告，至少一份受策略保护。等待清理后确认受保护报告仍可下载，对象引用只下降一次。对象引用归零时，确认物理回收发生在既有 GC 宽限期后。
4. 在一个批次中途停止认领实例，让另一实例接管。预期已提交项不会重复减少引用，同一报告只出现一条 report.retention.delete 成功审计。进行一次并发人工删除，确认计数与实际剩余引用一致。
5. 在批次进行中停用策略。预期停用成功后没有新的删除事务提交。核对运行状态、保留数量和审计时间线。

# P5 真机验收步骤

使用独立测试部署、MySQL 和对象存储。准备平台管理员、用户甲、用户乙，以及两个测试集群。两个集群均准备 payment 和 edge-system namespace。不要使用生产报告、真实凭据或生产集群。记录构建版本和部署副本数。

## 当前可执行的报告保留预览

1. 在两个测试集群分别生成 Markdown 和 JSON 报告，包含不同所有者。选一个集群和一种格式，准备三份早于截止时间、一份晚于截止时间的报告。可使用独立测试库中的历史报告或测试夹具，保持报告与对象引用完整。
2. 管理员打开智能体检中心的「保留预览」，选该集群和格式，设置保留天数为 1、最近份数为 2。预期共 4 份、保护 2 份、潜在候选 2 份。把最近份数提高到 4，预期潜在候选为 0。切换集群或格式应清空旧结果，重新计算只包含新范围。
3. 打开浏览器开发者工具的网络面板，确认预览请求为 GET /api/v1/report-retention/preview。普通用户登录看不到入口。用普通用户会话请求同一 URL，预期 403。管理员将 days 改成 0，预期 400。
4. 关闭预览后重新打开报告。预期报告数、下载结果和对象引用计数保持一致。若结果不符，保存请求参数、响应和筛选后的报告 ID。

## 长期记忆验收

先用管理员在配置中心启用 Memory，然后在 Chat 会话标题处打开「诊断记忆」。明确填写工作负载、主 namespace 和相关 namespace。首版要求提问包含完整工作负载名，例如 payment-api，且记忆范围与本轮授权相符。

1. 给甲授权集群 A 的 payment 和 edge-system 读权限。甲在 Chat 明确保存「payment-api 发布期间出现 502 时，对齐网关报错与旧 Pod 退出时间」，确认两个 namespace。取消保存一次，再重复确认同一个提交，预期最终仅有一条记录。
2. 甲在集群 A 新开 Chat 问 payment-api 502。预期展示记忆引用，并用当前证据排查。准备报错早于发布的测试数据，确认回答会排除旧解释。切到集群 B 发同样问题，预期无引用。
3. 给乙同样的集群 A 授权并发同样问题，预期看不到甲的记忆。撤销甲对 edge-system 的权限，在已有会话继续提问，预期从下一次模型请求起停止召回。恢复权限后修改记忆，验证下轮采用新版本，再执行遗忘，验证新会话与旧会话下一轮均不再召回。
4. 用专门设置的无害哨兵值测试 Secret 诊断。确认 ModelOnly 仅出现在授权的当前模型请求中，哨兵值不出现在记忆 API、SSE、对话历史、摘要、审计或记忆表。检查模型请求使用的是当前对话所选模型。

## 调度、审计与对象回收验收

等待策略激活、调度和审计接入后执行。使用双副本指向同一测试数据库和对象存储。仅对可删除的测试数据启用策略。

1. 带旧版 enabled=true 和 archive 配置升级，跨过一次调度周期。预期报告数量不变，策略需重新预览和激活。
2. 激活一个集群及一种格式的策略。预期仅移除符合年龄和最低份数条件的终态报告。活动依赖或无法确认生命周期的报告应保留。检查每条删除对应的运行明细和审计。
3. 准备共享同一对象的两份报告，至少一份受策略保护。等待清理后确认受保护报告仍可下载，对象引用只下降一次。对象引用归零时，确认物理回收发生在既有 GC 宽限期后。
4. 在一个批次中途停止认领实例，让另一实例接管。预期已提交项不会重复减少引用，同一报告只出现一条成功删除明细。进行一次并发人工删除，确认计数与实际剩余引用一致。
5. 在批次进行中停用策略。预期停用成功后没有新的删除事务提交。核对运行状态、保留数量和审计时间线。
